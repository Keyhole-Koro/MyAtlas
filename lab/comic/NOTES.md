# マンガで読む（comic）

## アイデア

流れ（flow）の 1 手順を、マンガの 1 コマにする。

- コマの中では、手順の 2 つの箱が**キャラクター**として立つ。関数は「名札を体にした人」、置き場は棚や列（要求の列は封筒の並ぶ筒、DOM は小さな木）、タイマーの時計は目覚まし時計の頭をしたレジスタ。
- キャラクターが立つ**床の色と名前が層**。2 人の層が違うときは床が段になり、上の層の人は台の上に立つ。台の側面には、そのあいだで通り過ぎる層が帯で見える（例：`request(m)` から `OS_CALL` へは、ライブラリの台の下に OS サービスの帯があり、その横を通ってカーネルの床へ降りる）。
- **ふきだし**が verb。ふつうの丸いふきだし、割り込み・通知や「顔の無い物（置き場・機械）」から出るものはトゲトゲ、syscall は太い角枠。ふきだしの文字は、かなを明朝・漢字をゴシックにした「アンチック」風（マンガの写植の慣例）。
- **手渡す物**がデータ。Request・Event は封筒、構造体は書類、`&Request` のようにアドレスだけのものは札、文字列（`s0, s1`）は「字」の印の付いた字の札、語の並び（`24 語`）は束、`i32` などの数は丸札。下の小さな字は、そのコマで大事なフィールド。
- 手渡す物は**矢印に重ねない**。同じ床では、低い矢印の上に名札のように置く（小さな物で間に余裕がある時は、平らな弧の下に吊るす）。線種と矢印の頭はどのコマでも見える。床が段になるコマでは、物は弧の途中に乗って矢印の頭から離れ、手のあいだに入らない時は、下の床の人の上の空で待つ（その人が話す時は弧の上）。ふきだしは、物・小道具・相手の体を避ける位置をいくつか試して選ぶ。
- 手順の文は、コマの左上の**ナレーション枠**。中のコード名（`send_text`、`REQUEST_SPACE` など）は等幅。その下に、どこで走るか（実行の文脈）を点線の札で書く。文脈が変わるコマでは、2 人のあいだに点線の壁が立つ。
- **分かれ道**（branches）は、コマの下の欄外に吊るした注。コマの段の高さを変えない。
- 「もし」（alt）は、元の手順のすぐ後に、点線枠の「もしも」の段として並ぶ。
- **中の紙**（paper）は、コマの下の縁にある虫めがねから、すぐ下に「ズームイン」の枠として開く。中のコマも同じ描き方で、帯（band）が床になる。紙の中の紙（gateway の中の submit）も入れ子で開ける。
- 各話に**表紙**。題、コマ数、読み方の 4 行、**道のり**（層を帯にして、1 列 1 コマで「どの層からどの層へ」を矢印で描いた小さな図）と、**登場人物**を層ごとの床に立たせた図。床の帯には役割（`sub`）と、その人物が出てくるコマの番号。番号を押すとそのコマへ、人物を押すとその人物が出るコマだけが明るくなる。もう一方の話にも出る人物には「第2話にも」の札。
- コマの高さは、そのコマの絵の高さ（空を切る）。1 段のコマは床の高さだけをそろえる。
- **おまけ「実録」**：記録した 1 回の実行（Editor で「x」を打った）を、スレッドが切り替わるたびに 1 コマとして並べる。割り込みはトゲトゲの擬音、syscall は角枠（記録に service がある時だけ `OS_CALL(REQUEST)` などと書き、service の無い syscall は「syscall」と、直前の関数（`sys_wait_notification から`）を書く）、地図の節に当たる関数は層の色の札、第1話のコマに出てくる関数には、そのコマ番号の札（押すとそのコマへ）。表紙には打つ前と後の差（文字・題名・位置）と、どのスレッドがいつ走ったかの帯。
- 第1話のコマのうち、記録の中で同じ関数に入った所には「実録 Editor 220,653 命令目」の判子を付ける（1 から、最初の戻りの手前まで）。コマの並びの最初に「判子は Editor の記録で、タスクマネージャの記録ではない」という一行。手順の文にある関数を記録が通っていない所（1 コマ目：文は Label_text、記録では直前が Window_title）は、判子の下にそう書く。判子を押すと、おまけ「実録」のその所が光る。

## 使い方

- `http://127.0.0.1:8765/comic/` を開く。上のタブで 第1話「UI の要求」／第2話「CPU 時間」／おまけ「実録」。
- 表紙の**道のり**で、層の上り下りを先に見る（番号を押すとそのコマへ）。
- 番号の順に、左から右・上から下へ読む。右上の「読み方」に、床・ふきだし・手渡す物・矢印の凡例（コマと同じ描き方の小さな絵）。スマホでも上の「読み方」「1 コマずつ」から開ける。
- コマを押す（または Enter）と**大きく読む**画面。コマが拡大され、物が投げられ、ふきだしが出る。右（スマホでは下）には、層の床の小さな地図（このコマの「渡す」「受け取る」に印）、2 人の説明と型、渡す物の構造体の全フィールド（このコマで大事な行に色）、分かれ道、もしも、実録（直前に入った関数も）、コードの該当行（`../data/src` から読む）。← → で前後、Esc で閉じる（閉じると、読んでいたコマに戻る）。
- 虫めがねのあるコマでは「中をのぞく」で紙の中へ。紙の最後のコマでは「次」が「外の 5 へ ↩」「外の もしA へ ↩」のように行き先を出す（「もしも」の終わりは、その紙の出口（ports）がつながる外の手順へ）。紙の本筋の最後のコマには「ここで外へ」のボタンもある。
- 一覧でも、コマにフォーカスして ← → でコマを移れる。
- 表紙の人物を押すと絞り込み。床の帯の番号（ボタン）でそのコマへ。
- URL に状態が残る：`#ep=cpu`、`#ep=ui&open=os.gateway,os.submit`（紙を開いた状態）、`#ep=ui&read=os.gateway:8&trail=ui:3`（紙の中のコマを大きく読む）。
- 暗い配色（prefers-color-scheme）とスマホ幅（1 列）に対応。動きは prefers-reduced-motion で止まる。

## うまくいったこと

- **層をまたぐ手順が一目で分かる**。段の高さと台の側面の帯で、「どの層からどの層へ、何を飛ばして」が地図を見なくても読める。表紙の道のりで、話全体の上り下り（第1話なら 1 と 3 で降り（3 は 2 段）、4 で 1 段上がり、9〜11 で戻る）を最初に見せられる。
- 1 コマに 1 手順なので、線が交差しない。初めての人が最初に何を見ればよいかがはっきりしている（表紙 → 1 コマ目）。
- ふきだしと手渡す物で、「誰が・何をして・何を渡すか」がコマの絵だけで読め、ナレーションが補う。札（`&Request`）と封筒（Request）の違いで「アドレスだけ渡す」が見える。
- 物を矢印から離して置くので、矢印の線種（実線・一点鎖線・点線）と頭がどのコマでも見える。
- コマの高さを絵に合わせ、分かれ道を欄外に出したので、空のコマがほぼ無くなった（第1話の 3 列で、ナレーションと絵のあいだの空きは多くのコマで 10〜40px）。
- 表紙の登場人物図は、矢印の無い地図として働く。床の帯の番号を順に追うと道筋が分かる。
- 実行の文脈は、キャプションの点線の札と、変わる所の点線の壁の 2 段で示し、絵を混ませない。
- 中の紙をその場で開くので、外の流れとの位置関係を失わない。開いた枠の尾が虫めがねを指し、開くと虫めがねが上の帯の下に来るまでスクロールする。
- 大きく読む画面の小さな床地図・フィールド表・コード行で、絵から実物へすぐ降りられる。スマホでは 1 列（コマ → 説明）に並ぶ。
- 「実録」で、同じ道を本当に通ったこと（`send_text → request → OS_CALL(REQUEST) → request_gateway.request → … → request_channel.serve → ui_protocol.handle`、serve は別のスレッド compositor.run で約 17 万命令後）が数字で見え、判子とおまけのあいだを行き来できる。
- 文字は 11px 未満なし（狭い所では、長い名前を SVG の textLength で少し詰める）。ライブラリは rough.js だけ（vendor/rough.js、28 KB）。

## うまくいかないこと・限界

- キャラクターはどの関数も同じ形で、見分けは名前と色だけ。マンガとしては個性が薄い。
- コマ割りは「3 コマずつ、もしもの所で切る」だけ。2 コマの段は幅が広い。1 段のコマは床をそろえるので、隣より絵の低いコマには上に空きが残る（第1話の 2 は約 110px、5 は約 60px）。
- 配置は手作りの規則。狭いコマ（スマホ幅の入れ子の紙など）では、名前は 2〜3 行に折れる。床が段になる狭いコマで、下の人が話す時は、物の札と矢印の頭が近い（700px 幅の第2話 11 など）。
- 分かれ道は欄外の文字の一覧で、絵（道しるべ）にはしていない。
- 道のりは本筋のコマだけで、「もしも」は描かない。どの箱かまでは描かず、層だけ。
- 実録の判子は第1話だけ、最初の戻りの手前まで。記録は Editor のもので、タスクマネージャのものではない。第2話の割り込みの道は、記録の中で原因を見分けないと合わせられないので付けていない。
- おまけの「実録」は、スレッドごとの関数の並びで、絵というより絵コンテ。長い回は札が 30 個以上並ぶ。syscall の種類は、記録に service があるもの（OS_CALL）のほかは名前を付けず、直前の関数だけを書く。
- アンチック風の文字は、明朝体（Hiragino Mincho、Yu Mincho、Noto Serif CJK）が無い環境ではゴシックだけになる。
- コマを 1 つずつ動かす「再生」は、大きく読む画面の中だけ。一覧では動かない。
- URL の状態は replaceState で書くので、ブラウザの戻るでは前の状態に戻らない。

## 本体のビューアに持ち帰れそうなこと

1. **段（台）で層の移動を描く**：層をまたぐ手順を、高さの差と、通り過ぎる層の帯で見せる。手順 1 つの説明図やツールチップにそのまま使える。
2. **道のり**：層を帯にし、1 列 1 手順で「どの層からどの層へ」を線種付きの短い矢印で描いた、高さ 100px ほどの図。流れのタブの見出しや、地図の上の索引に向く。
3. **手順カード**：「ナレーション（label）＋ ふきだし（verb）＋ 手渡す物（data と大事なフィールド）＋ 2 つの箱」を 1 枚にした表示。スマホや、横の詳細パネルの上部に向く。
4. **step.kind ごとのふきだしの形**（割り込み・通知はトゲトゲ、syscall は二重枠）と、**data の形**（封筒・書類・札・字の札・束・丸札）。矢印の線種より覚えやすい。ラベル（物）は矢印の線に重ねず、矢印の上に置くと線種が消えない。
5. **登場人物図＋出番の番号**：矢印を描かない、層ごとの箱の一覧に手順番号を添えるだけの「索引としての地図」。最初の画面の入口に向く。
6. **キャプションの中のコード名を等幅に**、**実行の文脈を点線の札に**。分かれ道はカードの外の注に。
7. **中の紙をその場で開く**（虫めがねからの吹き出し枠、入れ子可）と、紙の最後から外の次の手順へ戻るナビゲーション（「もしも」の終わりは ports のつながる外の手順へ）。
8. **大きく読む画面の構成**：小さな層の地図で現在地、構造体のフィールド表でこの手順の行を強調、該当コード行の抜粋。
9. **実録の判子**：手順ごとに、記録でその関数に入った命令数とスレッド、直前に入った関数。手順の文と記録が食い違う所（文にある関数を通っていない）を自動で見つけて書く。判子と記録の一覧を相互にリンクする。

## レビューの後で直したこと

- **スマホの大きく読む画面**（高）：列が中身の最小幅（約 615px）まで広がり、受け取る側や判子が画面の外に出ていた。760px 以下では本文を 1 列のブロックにし（グリッドをやめた）、コマは画面の実際の幅で描く。`.mini-chips` は折り返し、コード・型の欄は `max-width:100%` と横スクロール。種類の札がコマの床に重なることも無くなった。
- **おまけの OS_CALL の誤り**（高）：service の無い syscall（記録の seq 124・306・428。どれも `sys_wait_notification` の直後で、`syscall.unsafe.mln:505` の WAIT_NOTIFICATION が処理する）まで「OS_CALL」と書いていた。`OS_CALL(…)` は service がある時だけにし、無い時は細い角枠の「syscall」と「sys_wait_notification から」。表紙の行も「トゲトゲは割り込み、角枠は syscall（OS_CALL など）」に直した。
- **もしも の札が文に重なる**（中）：大きく読む画面の「もし A／もし B」の札の幅に合わせて余白を取り、スマホでは文を札の下に回した。
- **判子が 2 つのアプリを混ぜる**（中）：判子を「実録 Editor 218,920 命令目」とし、コマの並びの最初に「判子は Editor で x を打った記録で、タスクマネージャの記録ではない」という一行を出した。1 コマ目には「記録では Label_text を通らず、直前は Window_title」と書く（手順の文にある関数を、前の判子からこの判子までに記録が通っていないかを調べて出す。出たのはこのコマだけ）。大きく読む画面には直前に入った関数を書く。
- **空のコマ**（中）：段ごとに同じ高さで描くのをやめ、各コマを背の高い舞台に描いてから一番上の絵の少し上で切る。段では床だけをそろえる。分かれ道はコマの下の欄外の注にした（段の高さを変えない）。台の高さも少し低くした（86/104 → 76/96px）。
- **スマホでの文字のはみ出し**（中）：名前空間（`request_gateway`）も体の幅で折るか少し詰める。分かれ道の行先は `overflow-wrap:anywhere`。置き場の札は、幅に入る行数に並べ直す（`words[24]` は 3 行）。物は 2 人の手のあいだに収め、入らなければ矢印の上に置く。`wrapIdent` は「, 」の空白を残し（`ipc.send(ch, w)`）、「(」の前で折り、`m)` のような 3 文字以下の切れ端を作らない（少し詰めて 1 行に戻す）。
- **同じ床で矢印が物に隠れる**（中）：物を矢印に重ねず、低い矢印の上に置く（小さな物は、角を越える平らな弧の下に吊るす）。白い縁取りは札だけにし、フィールド名は文字の縁取り（paint-order）にした。矢印の頭は物の後に描く。床が段のコマでも、物は矢印の頭から離す（手のあいだに入らなければ下の床の人の上へ）。ふきだしは、物・小道具・相手の体を避ける位置をいくつか試して選ぶ。
- **閉じた後に戻る所**（低）：読んでいたコマ（紙の中なら、開いていればそのコマ、無ければ紙を開いたコマ）へスクロールし、フォーカスを置く。
- **スマホで凡例が無い**（低）：「読み方」と「1 コマずつ」を小さなボタンで出し、凡例は全画面の重ね（閉じるボタン付き）にした。
- **もしA から外へ戻る行き先**（低）：「もしも」の終わりでは、その手順が着く箱が ports にあれば、外のその手順（gateway の もしA → 外の もしA）へ。本筋の終わりは外の次の本筋のコマへ（無ければもう一つ外へ）。「次」のボタンに行き先を書く。
- **丸札の意味**（低）：文字列には字の札、語の並びには束を足し、丸札は「数（i32・spent・% など）」とした。
- **小さな a11y・配置**（低）：登場人物の番号は、人物のボタンの外に並ぶ本物のボタンにした（Enter で飛ぶ）。コマは role=group（中の判子と虫めがねがボタンとして読まれる）。紙を開くと、虫めがねが上の帯に隠れない所までスクロールする。小さな床地図の名前の欄は、一番長い名前の幅にして折らない。
- 足したもの：表紙の**道のり**。判子 → おまけの記録の所へ、おまけの番号札 → 第1話のそのコマへ、のリンク。

確かめ方：Playwright で 390・560・700・820・1024・1180・1440px の幅を開き（紙はすべて開いた状態）、コマの中の文字が体やコマからはみ出していないか、物・ふきだし・体・札が重なっていないか、矢印の頭が物に触れていないかを数えた。はみ出しと重なりは 0 件。矢印の頭が物の札の角に触れる所が、床が段で下の人が話す狭いコマに残る（1440・1024・560px は 0 件、ほかの幅で 1〜3 件。頭は物の上に描くので向きは見える）。大きく読む画面、紙の出入り、Esc の後のフォーカス、番号ボタンのキー操作、判子とおまけの行き来も同じやり方で確かめた。

## ファイル

- `index.html`、`comic.css`
- `js/model.js`：flow・paper を「話」に変換（番号、もしも、虫めがねの位置、コード位置、記録との対応と食い違い）
- `js/draw.js`：コマの描画（キャラクター、置き場、時計、床と台、ふきだし、手渡す物、矢印、空の切り取り）、凡例の絵
- `js/main.js`：表紙（道のり・登場人物）、コマ割り、ズームイン、大きく読む画面、ポップアップ、読み方
- `js/trace.js`：おまけ「実録」
- `vendor/rough.js`：rough.js 4.6.6（MIT）。`npm install` で入れて bundled/rough.js を写した。
- `shots/`：スクリーンショット（main・zoom・reader・trace・dark・phone）
