# アイソメトリックの建物（isometric）

## アイデア

MyComputer を 1 棟の建物として、アイソメトリックの断面図で見せる。

- **階 = 層**。上から 4F アプリ、3F ライブラリ、2F OS サービス、1F カーネル、地下 B1 エミュレータ。床の縁の色が層の色。
  地下 B1 は角の下だけの小さな機械室（エミュレータの部品で地図にあるのはタイマーだけ）。
- **部屋 = 実行の文脈**（点線で囲んだ床）。部屋の色はそこで走るもの：青 = アプリのスレッド、紫 = service task、赤 = 割り込み。
  `ctx.user` は 4F と 3F にまたがるメゾネット。`ctx.syscall`（OS_CALL の中）は 2F の左翼と、エレベーターの 1F の足元。
  「OS_CALL の中」も青いのは、呼んだプロセスのスレッドがそのまま走るから（`ctx.syscall.run`）。
- **機械 = ノード**。関数は画面付きの箱、置き場は引き出しの棚、要求の列は荷物の載ったリング、DOM は木の印、タイマーは文字盤。
  中に紙（paper）がある機械には小さな紙の印が立っている。
- 建物は L 字（角が奥）。角の手前に **OS_CALL エレベーター**（ガラスの筒）が立ち、3F と 2F の境に「ユーザ空間 / OS」の線がある。
  **エレベーターの 1F の足元（ピンクの台）が `kernel.os-call` の機械**。OS に入る道はこのエレベーターだけ（`kernel.os-call` の説明「アプリから OS への入口は、この syscall 1 つだけ」）。
- 2 つの流れは同じ建物を使う。機械の位置は流れを切り替えても変わらない（地図として覚えられる）。今の流れに出てこない機械は薄く、名前はホバーで出る。

流れの手順は、建物の中の移動として動く。

| 手順の種類 | 見え方 |
| --- | --- |
| 呼び出し（call） | そのスレッドの「人」が廊下を歩く。別の階へは **はしご**（同じスレッドのまま） |
| syscall | 人が **エレベーター** で下りる。`OS_CALL` の箱へ行く時は 1F の足元まで、そこから 2F の gateway へ上がる |
| 戻り | 同じスレッドなら人が戻る。別のスレッドへの返事（REPLY）は荷物だけがエレベーターで上がる |
| 列を通す（msg） | 荷物だけが運ばれる |
| 通知（signal） | 光る点が線を走る（「光る線」） |
| 読み書き（data） | 破線の上をデータのチップが動く |

**手順と手順の間に人がどこにいるか**も、地図から決めている（`js/tour.js` の `choreograph`）。

- **待つ**：次の手順が別のスレッドのものになる時、syscall で自分の部屋の外に出ていたスレッドは、出た所へ戻って「待つ」の吹き出しを出す。
  UI の手順 6 の後、アプリのスレッドはエレベーターで 3F の `request(m)` へ戻り、REPLY が来るまで待つ
  （`transport.unsafe.mln` 35〜42 行：`OS_CALL(REQUEST)` が戻った後、`wait_for(TransportSignal::REPLY)` で待つ）。
- **迎える**：荷物や光が向かう部屋のスレッドは、そこへ来て受け取る。UI の手順 10 では、アプリのスレッドが `next()` へ歩いて TIMER の Event を受け取る。
  まだ出ていなければ、着いた時に現れる（手順 6 の service task、CPU の手順 1 の割り込み）。
- **消える**：割り込みは待たない。自分の最後の手順が終わると消える（CPU の手順 7 以降）。
- 同じ機械に 2 人いる時は、その手順で動く人が真ん中、ほかの人は脇に立つ（着いた後の位置で決める）。
- 地図に書かれていない呼び出しの戻り（CPU 手順 9 の後、`charge_elapsed` から `fill` へ）は、次の手順の始めに歩いて戻る。

渡すデータは箱（データ名が `&` で始まる、アドレスだけの時は白い箱）。手順の看板（番号・動詞・データ名）が荷物と一緒に動き、着くとラベルや番号を避けて止まる（離れて止まった時は着いた所へ細い線）。
エレベーターに乗っている間、看板は筒の左に並んで動く（筒の上の札と、右の「ユーザ空間 / OS」を隠さない）。
誰が運ぶかは、地図の regions（`ctx.*.run`）から求めている。文脈の外の箱（要求の列、`charge_elapsed` など）は、最後にそこへ来たスレッドを引き継ぐ。

## 使い方

- `lab/serve.sh` を起動して `http://127.0.0.1:8765/isometric/` を開く（`#ui/6`、`#cpu/9` のように手順を URL で指定できる）。
- 上のタブで「UI の要求」「CPU 時間」を切り替える。流れは手順 1 から始まる。
- 右の「▶ 順に流す」で再生。← → で 1 つずつ、Space で再生・停止、Home で最初へ。
  建物の上の薄い線と番号の丸が流れ全体の形。丸にマウスを載せると、その手順の札（番号・動詞・渡すもの）が白い札で出る。丸をクリックするとその手順へ。
  右の番号の列にマウスを載せても動詞が出る。「もし満杯なら（5 の代わり）」の行は、列が満杯の時の手順。
- 機械（またはラベル）をクリックすると右にカード（説明・呼び方・中身・形の図・出てくる手順・コード）。再生中なら止まる。
- 紙の印がある機械は、カードや手順の「中に入る」（Enter / ダブルクリック）で、その機械にズームして中の紙に入る。
  紙の中は帯（band）を階にした小さな建物で、入口と出口の旗が立つ。中で走るスレッドはパネルに出る。Esc か左上のパンくずで外へ。
- 建物の下が「見方」。「見方」を押すとたためて、建物が少し大きくなる（選んだ状態は覚える）。
- 「館内案内」で 70 項目すべてを階ごとに一覧・検索できる。紙の中の項目を選ぶとその紙を開く。
- 「記録を見る」で、Editor で「x」を打った 1 回の記録（279 件）を建物の上で再生。スレッドごとに人が立ち（名札は走っている人だけ）、
  記録がその関数に入ると機械が光り、割り込みは dispatch に稲妻と原因（タイマー・キーボード・syscall REQUEST など）が出る。
  地図に無いアプリのコード（`os_call` など）の間は、人は 3F のエレベーターの前（ユーザ空間の入口）に立つ。
  下の帯は横が命令数で、誰がいつ走ったか（editor・compositor.run・automation_ui.run・idle）。
- 右上の「追う」で、カメラが手順ごとに動くものへ寄る。1 回で収まらない手順（長いエレベーター）は読める大きさのまま動くものを追い、着いた所で止まる。
  左上に今の階のチップが出る。スマホ幅では最初から追う（チップは左下。記録を見ている間は左上で、光った機械をカメラが追う）。

## うまくいったこと

- 「層」「実行の文脈」「呼び出しの種類」が、階・部屋・移動手段という 1 つの比喩にまとまった。
  「syscall はエレベーターでしか下りられない」「service task は別の人で、光の知らせで起きる」「アプリのスレッドは自分の部屋で返事を待つ」が、文章を読まなくても絵で分かる。
- スレッドを人で表したので、UI の流れで 2 つのスレッドが同時にいること、CPU の流れで割り込み（赤）が消えた後にアプリ（青）が同じ `charge_elapsed` に来ることが見える。
- 文字は画面の px で決めている：ラベル 13/12px、番号 12.5px、看板 14px、部屋の札 12.5/12px（測った値：1440×900 で 13.2 / 12.1px、1280×800・1366×768・1536×864 でも 13.1px 以上）。
  1440×900 でカメラの倍率は 0.98（UI）と 1.0（CPU）。
- 止まっている時、番号・看板・ラベル・部屋の札・階の札・見方は重ならない（1280×800・1440×900・1536×864・1920×1080 の全手順を測って重なり 0。1366×768 は部屋の札 1 枚が階の名前の余白に少しかかるだけ）。
- 見方を建物の下の帯として場面の中に描いたので、どの画面幅でも建物を隠さない。
- 角が空いた：1F の角にはエレベーターの足元（OS_CALL）だけ。CPU の流れで `fill` `charge_elapsed` `CPU 時間の置き場` が左翼の端に縦に並び、手順 6・9・10 が読み分けられる。
- 同じ建物で 2 つの流れ・4 枚の紙・記録を見せられる。紙は「機械の中に入る」ズームでつながる。紙の中の紙（submit）でも外と同じスレッドの色。
- データの形（struct）のどの欄をその手順で使うかを右のカードで色付け。リング・木・表・リストは形の図を描く（数は地図の roles から）。
- ライブラリなし（素の SVG と ES モジュール）、コードは約 225 KB（スクリーンショットを除く）。ダークモード、スマホ幅、動きを減らす設定に対応。
  2 つの流れを最後まで再生しても、紙を出入りしても、コンソールにエラーは出ない。

## うまくいかないこと・限界

- 機械の位置は手で決めた（`js/building.js` の `MAIN_PLAN`）。地図に新しい箱が増えると、空いている翼の端に自動で置くだけなので、きれいに並べ直すには表を直す必要がある。
- 文字の大きさを保つので、小さい画面では建物に対してラベルが大きい。1280×800・1366×768 では階の名前が少し上下にずれたり、列ごと左へ寄ったりする（ラベルを避けるため）。
  1180 幅より狭いデスクトップ（タブレットを横にした 1024×768 など）では倍率が 0.5 まで下がり、ラベルは 11px 台で一部重なる。「追う」を使うと読める。
- 「待つ」「迎える」の位置は、手順に書かれたことから決める規則（syscall で出た所へ戻る、宛先の部屋のスレッドが来る）。地図に書かれていない待ち方（例えば service task が次の SERVICE を待つ場所）は描けないので、最後の機械の前に立たせている。
- 部屋の札は建物の外の空いた所に置くので、部屋から少し離れることがある（点線でつないでいる）。
- 動いている途中の看板は、ラベルの上を通ることがある（止まる時は避ける）。スマホでは画面が狭く、止まった看板がラベルや階の名前に少しかかる手順がある（階はチップに出ている）。
- 歩く道は廊下の折れ線で、長い道（2F の右翼から 3F の左翼など）は時間がかかる。手順の意味より移動が目立つことがある。
- 記録の再生で、紙の中の関数（`gateway.read` など）は持ち主の機械を光らせるだけ。`ipc.send` のように複数の場所から呼ばれる関数は、同じスレッドがその機械にいる時だけ数える。`os_call_router.handle` など建物に無いカーネルの関数はログにだけ出る。
- 紙の中は「階 = 帯」の小さな建物にしたが、帯が 2〜3 本なので建物らしさは弱く、空いた床も多い。

## レビューの後に変えたこと

レビューの指摘（高 3・中 6・低 7）はすべて直した。1〜16 はそのための作り直し、17 は直した後に全部の手順・画面幅で確かめて見つけたもの。

1. **人の立ち位置**（高）：手順の間の位置を先に全部計算するようにした（上の「待つ・迎える・消える」）。アプリのスレッドが OS の中（gateway）で待っていた誤りと、CPU 手順 9 で割り込みの人にアプリの人が重なって紫に見えた誤りを直した。重なりの譲り合いは着いた後の位置で決める。2 つの流れを再生して、同じ場所に 2 人が重なる瞬間が無いことを確かめた。
2. **文字の大きさ**（高）：画面の px で決める（`view.ls` = 1 / 倍率。ラベル・札・番号・看板・名札はこの倍率の `scale()` の中に描く）。倍率が文字の置き場所で変わるので、置いて測ってを数回くり返して決める。スマホの「追う」は倍率 0.9 より引かない。
3. **建物を小さく**（高）：地下 B1 を角の下だけの機械室にした。スロットの間隔を 106→100。階の札を細くした（番号と名前を 1 行）。B1 の札は 1F の札の下に並べ、点線で B1 の前の面につなぐ。
4. **番号の丸**（中）：ラベルより上に描く。ラベル・札・看板・人と重なる場所には置かず、道の上に空きが無ければ脇に置いて短い線でつなぐ。番号にマウスを載せると、その手順の札（動詞・渡すもの）が白い札で出る（「番号に動詞が無い」への答え）。
5. **看板の止まり方**（中）：ラベル・部屋の札・階の札・「ユーザ空間 / OS」・エレベーターの札・見方・番号・着いた機械を避ける場所を、着いた点のまわりで探す。エレベーターに乗っている間は筒の左に並んで動くので、動いている間も筒の上の札と「ユーザ空間 / OS」が見える。
6. **見方**（中）：右上の HTML の箱をやめ、建物の下の帯として場面の中に描く（カメラが一緒に収める）。たためる。スマホ幅だけ従来のたたんだカード。
7. **パネル**（中）：手順・紙・外へ出る・流れの切り替えのたびに、カードの先頭までスクロールを戻す。
8. **角の混雑**（中）：`charge_elapsed` と `CPU 時間の置き場` を 1F 左翼の 2・3 番へ（`fill` の下と隣）。角には機械を置かない。
9. **スマホ**（中）：「追う」の間、今の階のチップを出す。記録の再生でも光った機械をカメラが追い、階のチップを出す。手順の終わりに全部が収まらない時は、着いた機械とラベルに合わせて止まり、看板は画面の中に入れる。
10. **再生中のカード**（低）：再生中に機械のカードを開くと再生が止まる。
11. **紙の中のスレッド**（低）：紙の中の紙は外の紙と同じスレッド。決まらない時（UI の流れから `charge_elapsed` の紙を開いた時）は灰色で、パネルに「割り込み・アプリのスレッドのどちらからも呼ばれます」と書く。
12. **色**（低）：今の機械はその階の層の色と黒い縁で光る（青はアプリのスレッドだけ）。エレベーターのかごと紙の印も青をやめた。
13. **OS_CALL を 1 つに**（低）：1F の別の OS_CALL の箱をやめ、エレベーターの 1F の足元を `kernel.os-call` の機械にした。はしごでの回り道が消えた。
14. **部屋とはしご**（低）：部屋の範囲を機械・はしごと同じ格子で決める。はしごの意味を「同じスレッドのまま別の階へ」にした。
15. **記録の名札**（低）：名札は走っているスレッドだけ。地図に無いアプリのコードの間は 3F のエレベーターの前に立つ。
16. **その他**（低）：最初は手順 1 から。もしもの手順の行に名前（「もし満杯なら（5 の代わり）」）。看板の白い箱は `&` で始まるデータだけ。
17. **確かめて見つけたもの**：
    - 紙から 2 回続けて Esc で出ると、カメラのズームが一瞬逆向きに進み、viewBox が負になってコンソールにエラーが出ていた（重い描き直しの後、アニメーションの最初のフレームの時刻が開始より前になる）。進み具合を 0 未満にしないようにした。
    - スマホで記録を見る時、カメラが 1 つ前の出来事のスレッドを追っていた。今の出来事のスレッドを追うようにした。
    - 1280×800・1366×768 でラベルが階の名前に重なっていた。階の名前はその階の縁に沿って少し上下にずれ、それでも足りなければ列ごと左へ寄る。部屋の札はラベルと階の名前を避ける。
    - 手順のカードの「運ぶのは」を、通知では「知らせるのは」、読み書きでは「読み書きするのは」にした。

## メインのビューアが取り入れられること

1. **スレッドを「人」（色付きの印）で動かす**。呼び出しは同じ人が動き、通知は別の人が起きる。`ctx.*.run` から求められるので、地図の書式は変えなくてよい。
2. **手順の間の位置を 3 つの規則で決める**：仕事を渡したら syscall で出た所へ戻って待つ／荷物や光の宛先のスレッドが迎えに来る／割り込みは終わったら消える。地図の regions と手順だけから求まる。
3. **境界を 1 本の縦の通り道にする**。OS_CALL をエレベーター（どの層図でも 1 本の縦の帯）として描き、その足元をカーネルの OS_CALL にする。ユーザ空間と OS の境目と「入口は 1 つ」がはっきりする。
4. **文字の大きさを画面の px で決める**。図をどれだけ縮めても、ラベルと番号は 12px 以上のまま。
5. **見方を図の一部として描く**（カメラが一緒に収めるので、重ならない）。
6. **手順の看板を動くものに付ける**。番号・動詞・データ名を 1 つの札にまとめ、着いたらラベルや番号を避けて止める。
7. **全体の形を薄い線と番号の丸で常に見せ、今の手順だけ太く**。番号はラベルの上に、ラベルを避けて置く。番号にマウスを載せると、その手順の札が出る。
8. **使わない層を薄くして「この流れは通らない」と書く**。
9. **カードで struct の使う欄だけ色付け**、置き場には形の図（リング・木・表・リスト）。
10. **紙へ入る時に機械へズームしてから切り替える**。中の紙がどこにあるかを見失わない。
11. **記録の再生を同じ地図の上で**：命令数の帯（スレッドごとのレーン＋割り込みの刻み）と、地図上の機械の点灯を同期させる。

- `js/panel.js`：右のプレーヤー・手順カード・ノードカード・コード表示
- `js/directory.js`：館内案内
- `js/trace.js`：記録の再生
- `shots/`：スクリーンショット（main は UI の手順 6、follow は「追う」で手順 9 の REPLY がエレベーターを上がる途中、paper は gateway の紙の手順 3、trace は記録の 109 件目（syscall REPLY の割り込み）、dark は CPU の手順 5、phone はスマホ幅で手順 3 のエレベーターに乗っている途中）
