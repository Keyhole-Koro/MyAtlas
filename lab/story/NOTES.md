# 読み物で追う（story）

## アイデア

文書マップを「地図を読む道具」ではなく、**上から順に読める長い記事**にした。NYT や The Pudding の
スクロールで進む解説記事の形で、左に本文、右に図を置く（1200px より狭い画面では図が上、本文が下）。
図は本文に貼り付いていて、段落が画面の中ほどに来るたびに切り替わる。

- **序**：5 つの層を積んだ図（点 1 つが項目 1 つ）、層をまたぐ 3 種類、2 つの流れが層を「下りて、
  また上る」道すじ（乗り換え案内のような線）。題もそこから取った。
- **章の道のり（表）**：章の最初・点線の枠の説明・章のまとめでは、地図を縮めて見せるのをやめ、
  **1 行が 1 手順の表**を出す。左に層を列にした細い線（序の道すじの線を縦にしたもの）、真ん中に
  番号・見出し・「どこ → どこ」、右端に「走らせる文脈」（地図の点線の枠）の括弧。行を押すとその手順へ。
- **手順**：1 段落が 1 手順。図は地図の上でその手順の 2 つの箱に寄り、矢印に沿って点が流れる。
  段落は手順の文、行き先の項目の説明、渡すデータ（その手順に出てくるフィールドだけを意味付きで）、
  列の操作、分かれ道、コードの行。
- **中の紙は寄り道**：紙は最初はたたんであり、本文には「寄り道・中をのぞく」の見出しと「中に入る」
  ボタンだけが出る。このとき図は箱の外から、箱の中に縮めて描いた紙を見せる。開くと紙の手順が
  その場に現れ、図は箱の中へ潜る（submit の紙にはもう一段）。たたんだまま先へ進んでもよい。
- **もしも（alt）**：「もし満杯なら」の囲みで、代わりに起きる手順を警告色で描く。
- **記録**：Editor で「x」を打った 1 回を、スレッドごとの帯と割り込みの時間軸で見る。区切りごとに
  時間の窓が寄り、地図にある関数が名前付きで並ぶ。各区切りから、同じ関数を通る章の手順へ飛べる。
- **索引**：流れに出てこない項目も含めた 70 項目。

## 使い方

- `lab/serve.sh` で開き `http://127.0.0.1:8765/story/`。スクロールするだけで進む。
- `J` / `K` で次・前の段落へ（たたんだ紙の中は飛ばす）。上のナビで章へ、図の上の番号で手順へ。
- 章の道のりの表の行を押すと、その手順へ飛ぶ。「寄り道」の行は紙を開いてそこへ飛ぶ。
- 「中に入る」で紙を開き、「たたむ」「紙をたたむ」で閉じる。
- 下線の語・図の箱・記録の点に触れる（押す）と、その項目のカードが出る。
- 「コード」のボタンでソースが右から開く（`Esc` で閉じる）。
- アドレスの `#s-ui-4` `#s-ui-gateway-3` などで段落を直接開ける（たたんだ紙の中なら開いてから）。

## うまくいったこと

- **1 度に見るものが少ない**：今の手順の 2 箱と 1 本の矢印だけがはっきりしていて、ラベルは
  その矢印にだけ出る。終わった矢印は薄く残り、先の矢印はかすかに見える。
- **章の全体は表で一目に**：UI の流れが「アプリ → ライブラリ → カーネル → OS → ライブラリ → アプリ」と
  下りて上る形が、線の形でそのまま見える。文字は全部画面の大きさ（12px 以上）で、図の縮尺に関係ない。
- **中の紙に本当に潜る**：紙は箱の中に描いてあり、そこへ寄るので、どこの中にいるのかが体で分かる。
  左の帯の名前・見出しの「gateway の中 › submit の中」・小さな全体図が、今いる紙に切り替わる。
- **全部データから**：箱の並べ方も自動。本文も label・text・fields・ops・branches・ports から組んだ。
- **コードの行はソースで確かめてから出す**（下の「変えたこと」4）。
- 暗い配色、1200px 未満（図が上）、スマホ幅、動きを減らす設定に対応。ライブラリは使っていない。
- 自動の検査で、1440・1280（暗い配色）・1024・390px の 4 つの幅について、章の 66 場面すべて
  （紙を全部開いた状態）で、図の中の文字が 11px 以上、文字どうしの重なりなし、小さな全体図の下に
  文字なし、ページのエラーなしを確かめた。#s-… での直接の表示、J / K、紙の開閉、表の行、コードの行も
  ブラウザで動かして確かめた。

## レビューのあとで変えたこと

1. **章の全体図を表に替えた**。前は流れ全体の地図を 0.3 倍に縮めて見せていて、名前が箱からはみ出し、
   番号が重なって読めなかった。章の最初・点線の枠・まとめは、上の「章の道のり」の表にした。
   表は図の枠の実寸から組み、縦長なら層の名前を縦書きに、横長で低いなら横書きの見出しと 1 行の行に
   する。地図のほうも、遠いときの名前は箱の幅を超えない（縮めて、11px を下回るなら「…」で切る）、
   同じ 2 箱の間の矢印の番号は縦に重ねず横に並べる、紙の印は遠いと出さない、ようにした。
2. **1200px より狭いと図を上に置く**。本文の列は幅に合わせて伸び縮みする（1440px で約 32 字）。
   手順のカメラは、図の枠が小さくても近い描き方（名前空間・名前・説明）を優先し、余白を詰め、
   少しなら右側を切る。それでも収まらない長い矢印（スマホでの UI の 9、CPU の 5 など）は、
   着く側の箱に寄ってラベルを矢印の端の近くへ移し、矢印が図の外へ出る所に「serve から」の札を出す。
   図の上の番号の点は、入らなければ出さない。
3. **紙はたたんだ寄り道にした**。1 章は 22,946px から 12,563px（1440×900 で 14 画面）、全体は
   59,288px から 40,917px になり、1 章の 11 手順は続けて読める。たたんだ紙は、図が箱の外から
   中の紙を見せる。開けば前と同じように潜る。
4. **コードの行を確かめる**。code.json の「手順の行」は推定なので、ページを開いたときにソースを読み、
   その行が行き先を呼んでいるか（`name(`）、書いているか（`name =`）、返しているか（`return`）を確かめ、
   違えば数行下を探す。箱の名前が `owner = pid` のような代入なら、行き先の関数の中でその代入を探す。
   結果：gateway の 2 は 102 → 212、gateway のもし A は 136 → 137、charge_elapsed の 6 は 111 → 112 に
   直り、UI の 2 は確かめられないので行き先の定義を開く。8 つはそのまま確かめられた。ソースが読めない
   ときは「推定」と目に見える印を付ける。行のない項目（DOM）は「null 行」ではなくファイルだけを開く。
5. **スマホ**：帯の名前は縦書きをやめ、帯の左下の小さな札にした（今の手順のラベルにかかると消える）。
   `#s-…` で開いたとき段落が図の下に隠れないよう、フォントと配置が落ち着いてからもう一度その段落へ
   合わせる（`#index-h` も同じ）。索引が見えている間はアドレスを書き換えない。
6. **図の上に重なるもの**：パンくずは図の上の見出しへ移した。小さな全体図は、その場面でカメラが
   止まる位置に対して、箱がいちばん少ない角へ動く（どの角も今の手順にかかるなら消える）。点線の枠の札は、
   枠に沿って滑って帯の名前の列や全体図の下に入らず、入りきらなければ短い名前（`OS_CALL の中`）に
   替わり、枠のほんの端しか見えないときは出さない。遠いときも短い名前で出す。今の矢印のラベルは
   箱より上に描く（薄くなった箱がラベルにかぶっていた）。
7. 箱の中の小さな文字（列の中身・名前空間）を大きくし、近い描き方で止まったとき 11px を下回らない。
8. 動詞のない手順の見出しを、矢印の種類（「呼び出し」）ではなく行き先から作る（「handle へ」
   「tick へ戻る」「owner = pid」「t.last = now」など）。今の矢印のラベルも同じ。
9. 記録：引き出し線を名前の下にくぐらせ、名前に縁取りを付けた。スレッド名の列を最長の名前に合わせ、
   凡例を括弧のすぐ下へ。低い枠では帯を細くして軸まで入れる。日付は記録の時刻のまま（読み手の
   時間帯に直さない）。
10. 序の線の上を走る点が、動き出す前に左上に出ていたのを直した。本文の「右の図」は、図が上に
    あるときは「上の図」になる。序では流れの地図を隠し、図が小さいときは層の名前を大きくして細かい字を
    省く。章のまとめの各行に、渡すデータを添えた。

## うまくいかないこと・限界

- **長い**：50 段落、約 41,000px。順に読む前提で、地図を探し回るには索引と元のビューアが要る。
- **たたんだ紙の見せ方**：箱の外から見た紙は小さく、中の名前は「read_use…」のように切れる。
  形と並びが分かる程度で、読むには「中に入る」が要る。
- **長い矢印の手順**は、1440px でも遠い描き方（名前だけ）になる（UI の 9、CPU の 5）。
  狭い画面では着く側だけを見せる形にしたので、出る側の箱は札でしか分からない。
- **走らせる文脈の括弧**は「手順を動かす箱（データを読むときは読む側）が入っている点線の枠」から
  機械的に決めたもの。どの枠にも入らない箱（要求の列、charge_elapsed など）の手順には括弧が付かない。
- コードの確かめ方は文字の照合なので、呼び出しが別の関数を通る場合（`runtime.send` を通って
  `app_transport.request` へ行く UI の 2）は見つけられず、行き先の定義を開く。
- 記録の区切りは「スレッドが続いた間」で自動に切ったもの。見出しは事実（スレッド名・割り込み・
  OS_CALL）だけで、意味づけはしていない。
- とても速くスクロールすると途中の手順は飛ばして最後の手順へ寄る。

## 本体のビューアに取り入れられること

1. **全体は表、細部は地図**：流れ全体を見せるときは、地図を縮めるより「1 行 1 手順の表＋層を列にした
   細い線」のほうが読める。線の形で「層を下りて上る」が分かり、文字は常に画面の大きさで出せる。
2. **手順を 1 つずつ見せるときは、カメラを 2 箱に寄せて、ラベルは今の矢印にだけ出す。**
3. **意味のズーム**：遠いときは名前だけ。名前は箱の幅を超えさせず、縮めて足りなければ「…」で切る。
4. **中の紙は箱の中に描いて、そこへ潜る**。たたんでおけば「寄り道」になり、本筋の長さを変えない。
5. **コードの行はソースで確かめてから出す**：呼ぶ・書く・返すの照合だけで推定の誤りが拾える。
   export.py（または MyAtlas）で同じ照合をすれば、地図のデータそのものが正しくなる。
6. **重なるものは場所を選ぶ**：小さな全体図は空いている角へ、枠の札は枠に沿って見える所へ。
7. **長い矢印は着く側へ寄り、出る側は札で示す**（狭い画面）。
8. **記録から章の手順へのリンク**：区切りごとに、通った手順を挙げて飛べるようにする。

## ファイル

- `index.html`：骨組み。データは `../data/atlas.js` と `../data/code.js`。
- `js/model.js`：章・中の紙・もしもを読む順の場面に並べる。手順の見出し、手順を動かす箱と点線の枠。
- `js/map.js`：並べ方、矢印の道、描画、カメラ（近い描き方を優先、長い矢印の端へ寄る）、意味のズーム、
  箱に収まる名前、滑る枠の札、角を選ぶ全体図。
- `js/board.js`：章の道のりの表。`js/text.js`：本文・カード・索引・コードの行の確かめ。
- `js/timeline.js`：記録の時間軸と本文。`js/main.js`：スクロール、紙の開閉、移動、カード、ソース。
- `style.css`：配色（明・暗）と文字組み。1200px と 700px で組み替える。
- `shots/`：`main.png`（最初の画面）、`board.png`（1 章の道のり）、`step.png`（1 章の 3）、
  `paper.png`（submit の紙の中）、`dark.png`（暗い配色・記録 3）、`mobile.png`（390px 幅・長い矢印の手順）。
