# やりとり図をやり直す（seq-plus）

## アイデア

文書マップの 2 つの流れ（UI の要求・CPU 時間）を、きちんとしたシーケンス図として描き直した。
左に「手順の文」、真ん中に「矢印」、右に「記録の時間」を同じ行にそろえ、上から下へ読めば流れが分かる。

- **生存線（lifeline）を実行の文脈の下にまとめる**：タスクマネージャのプロセス・OS_CALL の中・service task・割り込みの中を点線の枠で囲み、枠は図の下まで帯として続く。カーネルで走る文脈は斜線。
- **層の色**：カードの上の帯・生存線・動いている間の棒が、その箱の層の色。
- **カードに役目を書く**：名前・名前空間の下に、地図の「説明」（値を属性に束ねる、取り出して振り分ける…）か、置き場の中身（cpu_time・kernel・idle、tick 数 24 ビット・進み 8 ビット）。
- **矢印は種類で描き分ける**：呼び出し・syscall・列を通す・割り込み/通知・値を読む/書く・戻り/返事。凡例は左上に常にある（スマホは「凡例」ボタン）。
- **中の紙は ref の枠**：箱の中に紙がある所は、その箱に入った手順の直後に「中の紙」の枠。開くとその場で広がり、紙の箱が新しい生存線になる。外と同じ節点は同じ生存線を使う（要求の列・タイマーの時計・CPU 時間の置き場・process.stats）。入れ子の紙も開ける。
- **紙を開くと、紙が描く外の手順は畳む**：紙の中で同じことを描いている外の手順は、外の矢印を消して、紙の枠の下に「⑤ 並べる ＝ 紙の 8」の札として残す。UI の要求で request_gateway.request を開くと、外の 5「並べる」と もしA「false」は紙の 8 と もしA になり、外の「もし [満杯でない] / [満杯]」は、紙の外に残る B「0 を返す」だけの「もし [満杯]」になる。CPU 時間で charge_elapsed を開くと、外の 5「時計を読む」と 6「足す」が紙の 1 と 4 になる。同じことが図に 2 回出ない。
- **もし（alt）と分かれ道**：alt の手順は元の手順と一つの「もし [満杯でない] / [満杯]」の枠。branches は「分かれ道」の枠で、選ばれない道の枠には行き先を灰色で書く（→ shell_protocol.handle、→ g_kernel_time…）。
- **動いている間（活性化の棒）**：呼び出しは入れ子。呼んだ側は、呼んだ先が終わるまで動いたまま（dispatch → tick → reschedule → charge_elapsed は 1〜6 まで重なって続く。send_text は app_transport.request が返事を受け取る 9 まで続く）。紙の中は 1 つの関数の部分が順に走るので、部分ごとの短い棒。紙を持つ箱は、紙が開いている間ずっと動いている。
- **右の列：記録の時間**：記録（Editor で「x」を打った 1 回）の命令数を手順の行に当てる。前からの差は対数の棒、色は走っていたスレッド。UI は 2 回、CPU 時間は 9 回あるので回を選べる。
- **記録で流す（r）**：記録に時刻がある手順だけを記録の順に流す。次の手順までの命令数を、次の矢印の横の大きなバッジが数え上げ、いま走っているスレッドと、途中でスレッドが替わったこと（「editor から切り替わった」）を出す。UI では gateway（220,653）から serve（393,474）までの約 17 万命令の間に editor から compositor.run に替わるのが見える。
- **全体の地図と、縦に読むと横に追う**：図が画面より横に広い時は、右下に全体の地図（枠が今見ている所。押す・引くとそこへ）。縦に読み進めると、画面にある行の矢印が見える所へ図が横にずれる。
- **詳しく（i）**：選んだ手順の行き先と種類、渡す struct（触るフィールドに色）、手順の箱の説明、コード（code.json の行、無ければ定義）、記録（命令数・スレッド・あいだに入った関数）。カードを押すと、その箱の説明・引数・この図での出入り。

## 使い方

- `lab/serve.sh` を動かして `http://127.0.0.1:8765/seq-plus/` を開く。
- ↓ / ↑（j / k）で 1 手ずつ。Home / End。選んだ矢印が青くなり、点が矢印に沿って動く。
- **Enter**：「中の紙」の行か、紙の直前の手順で、その紙を開く。紙の中で **Esc** を押すと閉じる。紙は 1 枚ずつ開く（別の紙を開くと前の紙が閉じる。入れ子の親は開いたまま）。**o** で全部開く／閉じる（全部開いた後は、1 枚閉じてまた開いても他は閉じない）。
- **i** で詳しく。**p** で自動で順に。**r** で記録の速さで流す。**t** で記録の列を出す／隠す。**n**（または左上の ◂）で手順の文を畳んで図を広く。**m** で全体の地図を隠す。**1 / 2** で流れを切り替え。
- 畳んだ外の手順の札（文の列と図の両方）を押すと、それを描いている紙の手順へ。
- カードにカーソルを当てると、その生存線に関わらない矢印が薄くなる。閉じた紙にカーソルを当てると中の手順の一覧（もしの道は「A（もし満杯）」）。
- URL のハッシュに流れ・開いた紙・選んだ手順・文の畳み・記録の列が残る。畳まれた手順を指すハッシュは、それを描く紙の手順に移る。
- 幅 760px 未満（スマホ）：手順の文が各行の上、矢印はその下。上の「凡例」で凡例のシート、「⋯」で順に見る・記録で流す・すべて開く・記録の時間。

## 記録の時間の当て方（作り話をしないための決まり）

記録は「関数に入った所」だけなので、次の決まりで当てた。当たらない行は「—」で、カーソルを当てると理由が出る。

1. 手順の行き先の節点が記録の `n` に出てくる関数なら、記録を前へたどって次に入った所の時刻を当てる（時刻は増える一方）。
2. 出どころの関数が、すぐ前に当てた関数と同じなら「続けて入った」（●）。出どころが置き場など記録に出ないものなら「入っただけ」（○）で、数字の下に入った関数を出す（例：「send_text に入った」）。
3. 出どころが関数なのに、この回で直前に入っていない時は当てない。
4. 値を読む・書く手順は、すでに入った呼び出しの中で起きるので、その時刻を「〃 同じ呼び出し」として当てる。
5. 戻り、もしもの道、置き場への手順、関数でない節点には当てない。
6. タイマーの割り込みの手順は、原因が timer の irq の時刻を当てる。
7. 記録は Editor の打鍵で、タスクマネージャのスレッドは出てこない。1 の時刻は view() ではなく Editor が send_text に入った時刻（○ の行に「send_text に入った」と出る）。

紙を開いて畳んだ外の手順は行が無くなるだけで、他の行の時刻は変わらない（旧版と新版の model・trace を全部の回・全部の紙の開き方で比べ、802 か所で差 0）。

## うまくいったこと

- 紙を開いても同じことが 2 回描かれない。畳み方はデータ（箱と節点、ports、もし・戻りの別）だけから決まり、今のデータでは UI の 5・もしA、CPU の 5・6 が畳まれる。
- 紙の生存線の置き場所を、外の矢印を伸ばさない所に選ぶ。UI で Tasks.tick を開くと、紙の線はタスクマネージャの文脈の左端に入る（前は tick() と OS_CALL の間に 5 本入り、3・9・10 の矢印が伸びた）。CPU 時間の Tasks.tick は tick() の左。gateway・submit・charge_elapsed は箱の右のまま。
- 呼び出しの入れ子が棒で読める。割り込みの中の 4 つの関数が重なって続き、アプリの 3 つの関数は返事が来る 9 まで待っている。
- 1 枚ずつ開く・全体の地図・縦に読むと横に追う、の 3 つで、紙を開いて横に広くなっても迷いにくい。
- 1440 幅で、紙を閉じた UI の要求（11 本）と CPU 時間（9 本）は横スクロール無し。見出し・文の列・記録の列は貼り付いたまま、図だけが動く。枠の題（紙の題・もしの題）は枠の左が隠れても見える所へずれる。
- 小さい灰色の文字を濃くした（明るい時 #686762、暗い時 #96958f）。ヘッダ・カード・文の列・記録の列の文字で 4.5:1 未満は 0（両方の流れ、明暗とも）。
- スマホ：凡例のシート、⋯ のメニュー、図の中のもしの題は出さない（文の行が言う）。1024 幅でも上の帯は 1 段（ボタンはアイコンとツールチップ）。
- 乱数のキー操作 4 通り（各 220〜260 回、幅 390〜1440）で、コンソールのエラー 0、SVG の NaN 0、選んだ手順とハッシュは常に正しい。

## うまくいかないこと・限界

- 紙を全部開くと、生存線は UI の要求で 29 本、CPU 時間で 18 本になり、横に長い。地図と横の追従で迷わないが、全体を一画面で読むことはできない（1920 幅なら CPU 時間の charge_elapsed は横スクロール無しで収まる）。
- 畳む対応は「紙の箱と、紙の中にも居る節点を結ぶ手順」から決める。外と紙で言い換えになっていても、節点でつながらない手順は畳めない。
- 活性化の棒は手順の種類から推している。明示の戻りが無い所は「呼んだ側がまた動いた時」か「流れの終わり」で切るので、実際に戻った時刻とは限らない。例：満杯でない時に OS_CALL(REQUEST) が戻り、アプリが OS_CALL(REPLY) で待ち直す所はデータに手順が無いので、app_transport.request の棒は 2 から 9 の返事まで 1 本で続き、OS_CALL の棒は満杯の時の B まで続く。
- UI で Tasks.tick を開くと、紙の枠の中に何もしない生存線（view() など 4 本）が通る。矢印を 4 本伸ばすより読みやすいと判断した。
- 記録の時刻は「行き先の関数に入った時刻」で、手順そのものの時刻とは限らない。タスクマネージャ固有の手順（tick() に入る 11、CPU 時間の 7〜）には付かない。
- 分かれ道の 2 番目以降は行き先が図に無いので、矢印ではなく行き先の名前だけ。
- スマホでは図が横に長い（文の行を押すとその矢印へ、縦に読むと横に追う）。
- 名前と役目の折り返しは Chromium の `word-break: auto-phrase` を前提に調整した。

## 本体のビューアに取り込めること

- **手順の文・矢印・記録の時刻を同じ行にそろえる 3 列**。図だけで読ませない。
- **中の紙をその場で開く ref の枠と、外の手順を畳む規則**：紙の箱と、紙の中にも居る節点（同じ節点か ports）を結ぶ外の手順を、紙の対応する手順に置き換え「＝紙の 8」と残す。もしの枠は残った道だけにする。これで紙を開いても図が嘘にならない。
- **紙の生存線の置き場所のコスト**（横切る外の矢印 × 本数 ＋ 紙の矢印の長さ ＋ 枠の中の空き線）。
- **活性化の棒の 2 つの読み方**：流れでは呼び出しの入れ子、紙の中では関数の部分の順。
- **1 枚ずつ開く紙、全体の地図、縦に読むと横に追う図**。
- 生存線のカードに box の sub や置き場の slots を出して、役目をカーソル無しで見せる。
- 記録の当て方の決まり（続けて入った／入っただけ／同じ呼び出し、当てられない理由）と、回の選択、記録で流すバッジ。
- `word-break: auto-phrase` による日本語の折り返しと、はみ出した枠の題をずらす仕掛け。

## レビュー後に変えたこと

- **（高）紙を開くと同じことが 2 回描かれた** → 外の手順を畳むようにした（上の規則）。畳んだ手順は紙の下に札で残し、押すと紙の手順へ。もしの枠は残った道だけ。畳まれた手順を選んでいた時やハッシュは紙の手順に移り、紙を閉じると元の外の手順に戻る。
- **（中）開閉の途中で流れを替えると壊れた** → 流れを替える時に動きを止め、await の後で流れが替わっていたら何もしない。存在しない手順は選ばない。途中で止まった開き方でも、選ぶのは紙の最初の手順。
- **（中）紙を開くと横に広がり全体が見えない** → 1 枚ずつ開く、生存線の置き場所のコスト、全体の地図（m）、縦に読むと横に追う、手順の文を畳む（n）、すべて開いた後は表示中の手順へ横に動く。
- **（中）活性化の棒が入れ子の呼び出しを階段に描いた** → 呼び出しの入れ子として描き直した（紙の中は部分の順のまま）。同じ線で重なる棒はずらす。
- **（中）小さい灰色の文字のコントラスト不足** → 色を濃くして 4.5:1 以上に。
- **（中）スマホに凡例とボタンが無い・もしの題が 2 回** → 凡例のシート、⋯ メニュー、図の中の題を隠す。
- **（低）凡例が列からはみ出した** → 列幅に収まるよう組み直した（1440 でも 1024 でも収まる）。
- **（低）選ばれない分かれ道の枠が空** → 行き先を灰色で書く。
- **（低）○ の時刻が何の時刻か分からない** → 入った関数を数字の下に。
- **（低）文の細部** → 記録の題を文節で折り返す、「割り込みの中 割り込み」の重複を消す、閉じた紙のプレビューは「A（もし満杯）」、凡例に「前からの差（対数）」。
- **（低）Enter が 2 つのことをした** → Enter は紙を開くだけ。詳しくは i。上の説明も合わせた。
- **（低）記録で流す時の手がかりが小さい** → 次の矢印の横に大きなバッジ（命令数・スレッド・切り替わり）。
- **（低）狭いデスクトップで窮屈** → 1280 未満で文の列と記録の列を細く、上の帯を 1 段に、ボタンはアイコンに。文の列は畳める。
- **（低）開く途中のカードの文字がはみ出した** → 列が 7 割の幅になるまでカードの文字を出さない。
- **レビューに無かった不具合**：配置し直すたびに、作り直さなかった文の行が 12px ずつ伸びていた（「すべて開く」の後に行間が広がる）。行の高さを毎回、文の自然な高さから測るようにした。

## ファイル

- `index.html`・`style.css`
- `js/model.js`：行・枠・畳む手順（foldMap）・生存線と紙の線の置き場所（placeBlock）・活性化の棒を、データから組み立てる（DOM を使わない。node でも動く）
- `js/trace.js`：記録を行に当てる（変えていない）
- `js/app.js`：配置・描画・アニメーション・地図・横の追従・キー操作・詳しく・記録で流す
- `js/util.js`：文字幅、折り返し、コードの色分け
- `shots/`：main.png（1440×900）、paper.png（紙を開いて畳んだ所、1920 幅）、cpu.png（charge_elapsed を開いた CPU 時間、1920 幅）、all.png（すべて開いて入れ子の紙と地図）、record.png（暗い画面で記録を流す途中）、phone.png（スマホと凡例のシート）
- ライブラリは使っていない（vendor/ は無い）。
