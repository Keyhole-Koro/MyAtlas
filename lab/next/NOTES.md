# 次のビューア（next）

ラボの 14 の試作から良い所を集めて、1 つのビューアにまとめたもの。本体の MyAtlas ビューアがこれからどうなるとよいかを、
動く形で見せる。見方は 5 つ（歩く・地図・やりとり・記録・データ）。どの見方でも、選んだ手順と節は同じで、
アドレス（`#v=walk&s=ui:3/os.gateway:1&n=os.gateway`）に今の場所が残る。

2 つのレビュー（初めて読む人とデザイン、事実と作り）のあとで、指摘の high と medium をすべて、low の多くを直した
（「レビューのあとに直したこと」）。

## 開き方

- `lab/serve.sh` を動かして `http://127.0.0.1:8765/next/`。
- このフォルダだけで動く（データの写しを `data/` に持つ）。ファイルとして直接開いても（file://）、
  オリジンの無いサンドボックス（artifact サイト）に置いても動くように、読み込みはすべて相対パスの
  普通の `<script>`（モジュールも fetch も使わない）。localStorage は色の好みと図とコードの境目だけで、
  try/catch の中。無くても動く。サービスワーカーもネットワークも使わない。
- データを取り直したら：`python3 lab/export.py` のあと `node lab/next/tools/sync-data.mjs`
  （`data/atlas.js`・`code.js`・`sources.js`・`trace-full.js`・`metro-layout.js` を作り直す）。
- 確かめ直すには：`node lab/next/tools/check.mjs`（下の「確かめたこと」を全部流す。`--quick` で大きさを減らす）。

## 使い方

上の帯：題「次のビューア」、流れの切り替え（UI の要求／CPU 時間）、見方の切り替え、節と手順をさがす（`/`）、
色（システムに合わせる → 明るい → 暗い）、使い方（`?`）。自動で歩いている間にほかの見方へ移ると、帯に
「自動で歩いています 3 / 28」と「止める」が出る。

### 歩く（開いた時の画面）

- UI の要求の手順 1 から開く。データの `start`（手順 5）は「地図のはじめ」の札で示し、その手順のカードには
  「地図が最初に見せる手順（データの start）」と書く。
- 「最初から歩く」（Space）を押すとすぐにボタンが「止める 1 / 28」に変わり、今のカードが光り、1.5 秒で手順 2 へ。
  そのあとは 3.6 秒ごと。紙があれば 1 度ずつ入って出てくる（UI は 28 か所、CPU 時間は 23 か所）。
  どこかで手順を選ぶ（地図・やりとり・記録・データ・さがす・節のカード）と、自動は止まる。
- 上の右：**道のり**。1 列が 1 手順、行が 5 つの層。1 本の線が層を上り下りし、着いた先の層の色の点を打つ。
  通った所は落ち着いた 1 色、今は青で太く矢じり付き、これからは灰（読める濃さ）。列を押すとその手順へ。
  紙の中では紙の帯（アプリのメモリ・関数の中・OS 側…）に替わる。帯の名前は測って幅を決めるので、スマホでも切れない。
- 左：**手順の列**。番号・動詞・種類、その下にどの箱からどの箱へ（すべての行に。「もし」の A・B にも）。
  通った手順の動詞は落ち着いた青灰、これからの手順は灰、番号を通る細い線（通った所は色付き）。
  今の手順は**カード**：動詞が題、手順の文、渡すデータのフィールド、操作、分かれ道、文脈（変わる時は
  「文脈が変わる A → B」）、記録、地図とコードの食い違い（あれば）。中の紙は字下げした手順の列として開き（Enter）、
  見出しが上に貼り付く（Esc で外へ）。
- カードの**記録**は 2 つの数を分けて書く：「この手順は 2 回」（記録の見方が枠を付ける呼び出しと同じ数え方。
  「記録で見る」で記録の見方へ）と、「syscall.dispatch に入った：OS_CALL の中で 9 回（ほか WAIT_NOTIFICATION の中 3）」
  （行を持つ関数に入った回数を、入った時の文脈で分けたもの。文脈は記録の割り込み・syscall の段から決める）。
  記録していない関数なら「〜は記録していない関数。この手順は記録からは言えない」。
- 右上：**やりとり図**。手順と一緒に進む。今の矢印は青く太く、番号の札はいつも出す。紙に入ると、その紙が
  図の中でその場に開き、紙が描く外の手順は「並べる ＝ 紙の 8」の札に畳まれる。図の欄が低い時（360px 未満）は、
  生存線の頭を 1 行（名前だけ）にして手順を多く見せる。
- 右下：**コード**。行が分かる手順（code.json の「起きる行」、lines.js の「たぶんここ」、欄）では開き、
  行の真下に吹き出し。箱しか分からない手順では見出しの 1 行（ファイル・関数・「行は分からない・箱のコード全体」・
  「コードを開く」）にたたみ、図が広くなる。行が箱の関数の外にある時（UI 8 は handle が呼ぶ run_request の 84 行）は、
  帯をその行を持つ関数にして「run_request の中・ui_protocol.handle が呼ぶ」と書く。
  地図とコードが食い違う手順（13 語と 15 語など）は、カードと吹き出しに「!」の注意を出す。
- キー：`←` `→` 手順、`Enter` 中の紙へ、`Esc` 外へ、`Space` 歩く・止める、`Home` `End`、`/` さがす、`?` 説明、
  `1`〜`5` 見方。ボタンをマウスで押したあとも、Enter と Space はこの意味のまま（押したボタンからフォーカスを外す。
  Tab で選んだボタンは Enter・Space で押せる）。
- スマホ：1 列。手順は横に流れる札、今の手順のカード、その下で「やりとり図」と「コード」を切り替える
  （コードに替えると手順の行で開く）。下に前へ・中の紙へ・次へ。

### 地図

路線図。流れと中の紙が路線、節が駅、同じ節は乗り換え駅、層は地区。全体が 0.8 倍以上で入る時は全体を、入らない時は
今の手順の線（それも入らなければ今の区間）を読める大きさで見せる。今の手順は線の上に番号と動詞の札で出す。
札は駅の名前・駅・始発の札・線の印・地区の名前を隠さない所（両側、線から 90 単位まで、引き出し線付き）に置き、
そういう所が無い時は番号だけの丸にする。左の路線を押すとその線を時刻表に（線の中に「›」、区間ごとの番号）。
時刻表の行を押すとその手順を選ぶ。「始発」の札か「1 から歩く」で、その線を手順 1 から歩く（紙の線は、その紙に入る手順から）。
駅を押すと節のカード。ドラッグで移動、ホイールで拡大、`0` で全体。スマホでは地図が全面で、路線と時刻表は下から引き出す。

### やりとり

手順の文・矢印・記録の時刻を同じ行にそろえた 3 列。生存線の頭に、その箱がすること（「値を属性に束ねる」など、
地図の `sub`）を 2 行まで書く。中の紙は「開く」でその場に開き、外の手順を畳む。「中の紙をすべて開く」、記録の時間の表示、
記録の何回目か（UI は 2 回）。`↑` `↓` で 1 手ずつ、`Enter` で紙へ、`Esc` で閉じる。
スマホでは図を描かず、手順の行の中に「どの箱 → どの箱」と種類を書く（図は歩くのやりとり図で見る）。

### 記録

Editor で「x」を打った 1 回を、スレッドごとの呼び出しの段（フレームグラフ）に。上に記録全体の細い帯
（場面・その時 CPU が走っていた層・今見ている範囲の四角。押すとそこへ、引くと動く）。横は命令数で、記録した関数が
何も開いていない長い間は詰める（「実際の長さ」に切り替えられる）。斜線は CPU を離れて待っていた間。
列を通った要求・返事・イベントの矢印は名前の下を通り、矢印の名前（要求・返事・イベント）は場面のピン・呼び出しの名前・
ほかの矢印の名前に重ならない所にだけ置く（置けなければ名前を付けない）。右に今の手順（この記録で何回か）、まとめ
（命令の数、3 スレッド＋走るもの無し・242 回の呼び出し・割り込み 23 回・528 イベント、記録した関数の中と外の割合、
どの層で走ったか）、キー → DOM の道筋（待ちの割合 85%）、OS_CALL の数え方（9 回・58,270 命令）。
ほかの見方で選んだ手順に当たる呼び出しに枠が付き、ほかは薄くなる（暗い色では薄くしすぎない）。

### データ

UI の要求では Request の 10 のフィールド（と外から加わる 5 つ）× 22 手順（中の紙をその場に開いた）。1440 の幅で 22 列が
すべて入る。列の番号は歩くと同じ（紙の列は紙の中の番号、紙の帯に「4›」「4›8›」と入口を書く。外の 5「並べる」を描く紙の 8 には
「＝5」）。線の色は値のあるメモリ（アプリ・OS 側・まだアプリの値を指す OS 側は斜線）。印の凡例（写す・読む・上書き・
この要求ではしない・#n・0・運ばれるだけ・!）。owner の上書きは赤い印と「ここが要」。列を押すとその手順を選び、右に地図の文の
引用とコードの行が出る。表を下へ送っても、見出しは印の上に残る。CPU 時間では時計 → CPU 時間 → % の値。

### 節のカード（どの見方からも）

種類・層・シグネチャ・説明（`[[リンク]]` は層の色のチップで、指すと中身の下見）・引数と返す値・アドレス（レジスタ）・
形（リング・木など、コードの名前と数、操作と手間 O(1)、不変の決まり。要求の列のように別の節の形を借りる時はそう書く）・
フィールド・値・状態の移り変わり・走るもの・コードの場所（行番号は途中で折れない。「コードを開く」で歩くのコード欄に寄り道）・
中の紙を歩く・出てくる手順（押すとその手順）・指しているもの（だれが・なぜを文ごとに）・記録が言えること。

## レビューのあとに直したこと

high（5 つ、すべて）

1. 「最初から歩く」が 3.6 秒何も変わらない → 押すとすぐボタン・進みの帯・カードが変わり、最初の 1 歩は 1.5 秒。
2. スマホの地図の文字が 5〜7px → svg の実際の大きさに合わせて viewBox を直し（ResizeObserver）、地図を全面に、路線は下の
   引き出しに。開いた時は今の手順の辺りを読める大きさで。地図の上の札（始発・線の印・区間の番号・今の手順）は 14 単位にして、
   0.8 倍でも 11px 以上。
3. データの見出しに印が透ける → 見出しを印と行の名前より上に重ねる（z-index）。見出しの「ここで」の札は 1 つの欄にまとめて置く。
4. 地図やさがすで選んだ手順を自動が上書きする → 自動の外で手順が変わったら、どこからでも自動は止まる（`NX.set` で 1 か所）。
   ほかの見方にいる間は、上の帯に止めるボタン。
5. さがすが何にでもすべての節を返す → 当たらない物は出さない（「見つかりません」）。

medium（すべて）

- 地図の今の手順の札が駅の名前を隠す（51 のうち 12）→ 隠さない所だけに置く。3 つの大きさで 0。
- 記録の名前の重なり → 矢印を名前の下に、矢印の名前は空いた所だけに。全体の帯とまとめを戻した。
- 歩くが落ち着かない・図が小さい → 図 62%・コード 38% を基本に、箱しか分からない手順ではコードを見出しだけにたたむ。
  低い欄では生存線の頭を 1 行に。
- 通った手順とこれからの手順が同じに見える → 動詞の色と太さを分け、番号を通る線を引いた。
- 「もし」の行が読めない → すべての行に「どの箱 → どの箱」。
- 見方によって記録の数が違う（12・2・9、23・9）→ カードも記録の見方も同じ当て方（trace-model の stepHits）で数え、
  関数の回数は入った時の文脈で分けて別に書く。割り込みの中を数え分けず、戻りの手順を出る側の文脈で数えていたのを直した。
- 13 語と `words[15]` が並んでも何も言わない → カード・吹き出し・やりとりの文・時刻表に「!」と食い違いの説明。
- UI 8 でコードの見出しが別の関数の名前 → 行を持つ関数（run_request）を帯にして、呼ぶ側を添える。
- データの表が 13 列しか入らない・番号が違う・凡例が無い → 列幅を固定して 22 列、歩くと同じ番号、印の凡例。
- 道のりが薄くて読めない・「はじめ」が分からない → 1 本の線と層の色の点、「地図のはじめ」と書き、カードに 1 行。
- マウスで押したあと Enter・Space がボタンを押してしまう → マウスで押したボタンはフォーカスを返す。
- スマホでコードを開くと 1 行目 → 欄が見えてから手順の行へ送る。
- 節のカードに形・操作・不変・アドレスが無い → 加えた。

low（安く直せたもの）

- 節のカードのコードの場所が行番号の途中で折れる → パスだけ折る。
- スマホで道のりの帯の名前が切れる・コードの見出しが長い → 名前を測って幅を決める、スマホでは見出しをファイル名だけに。
- 1024 で地図が左右に切れて OS_CALL が見えない → 全体が入らない時は今の線（か区間）に寄せて開く。
- やりとりの生存線の役目の 1 行が消えていた → 頭に 2 行まで（語の途中では折らない）。
- さがすの並び → 名前・動詞がそのものの物を先に、節と手順を 1 つの列に、今の流れの手順を少し先に。
- 場面の札で「命 / 令」と折れる・「定義 24–24 行」・分かれ道の枠の文字が「→ ui…」で切れる・暗い色で薄い呼び出しが消える・
  地図の文字の大きさがばらばら → それぞれ直した（分かれ道の枠は文字が入る幅まで右へ広げる）。
- 記録の見出しの数（4 スレッド・265 回）→「3 スレッド＋走るもの無し・242 回の呼び出し・割り込み 23 回」。
  当たる所が無い時に「端の関数に入った所を当てた」と書いていた → 書かない。「記録していない関数」は記録の `watched` で決める。
- 試作の焼きなまし（`anneal`・`evaluate`）をページの写しから外した（9 KB）。
- `<small>` が 9.2px になっていた → 11px。

直さなかったこと：見方ごとの JavaScript を開いた時に読む形（lazy load）にはしていない。測ると、最初の描画は約 0.13 秒、
読み込み直後の長い処理は約 0.18 秒（CPU を 4 倍遅くして 0.34 秒）で、その大半は最初の画面を描くこと自体だった。
地図・データ・記録・やりとりの見方のコードを後で読んでも 160 KB ほどで、得は小さい。seq-plus の「記録で流す」も戻していない。

- エラー：両方の流れの自動の 51 手順 × 5 つの見方を、1440×900（明るい・暗い）、1024×768、390×844（明るい・暗い）で。
  70 の節のカードを全部開く。コンソールのエラーと読めなかったファイルは 0。

  （SVG の文字は描かれた縮尺で測る）。

  始発の札・線の印を隠す手順は、1440・1024・390 で 51 のうち 0（番号だけの丸になるのは 1440・1024 で 4 手順）。
  記録の矢印の名前がピンか呼び出しの名前に重なるのは 0（1440・1024・390、暗い色でも）。

  色の切り替え（保存は例外を出すが無視する）・見方の移動がエラーなく動く。

## まだ足りないこと・限界

- やりとり図は紙を開くと横に長い（UI で gateway を開くと 20 本）。歩くでは今の矢印へ横に動くが、全体のミニマップは無い。
- 「たぶんここ」の行は lines.js の字句の推し方。データが変われば外れることがある（だから点線で出す）。
- 地図は保存した配置に頼る。駅が増えた時は保存した配置から近くに置くだけ（作り直しは metro の tools）。地図を自分で
  0.8 倍より小さくすると、名前も 11px より小さくなる。
- 記録は Editor の 1 回だけで、タスクマネージャの手順（UI 11、CPU 7〜）には当たる呼び出しが無い。記録の段は canvas なので、
  キーボードで 1 つずつは選べない（右の一覧から寄れる）。節のカードを開いても、記録の段では光らない（手順だけ）。
- 地図とコードの食い違い（!）は data-journey の手書きの対応表から出るので、UI の要求の 3 手順だけ（13 語と 15 語、result_out の条件）。
- データの表は UI と CPU の 2 つの旅だけ。パケット（動き）は持ってこなかった。
- ブラウザの戻る・進むは、見方・流れ・紙の出入り・手順を押した時・節のカードを 1 つずつ戻る。← → と自動で歩くは履歴に積まない。
- 読み込みは 32 ファイル（ソースの写しを除く 805 KB、gzip で 197 KB）。最初の画面を描いてからソースの写しを読む。

## MyAtlas 本体へ移すには

ビューア（`viewer.html`）は 1 枚の HTML に地図を埋め込む作り。このページの `js/` と `css/` をそのまま `viewer.html` に
インラインし、`data/*.js` の代わりに build.py が埋め込むデータを読めばよい。データ側に足すものは次の通り。

1. **手順の行と確かさ**：`build.py`（`export.py` と同じく）が、手順ごとに `{path, line, how}` を出す。
   how は「step（呼び出し・代入・return を確かめた行）」「focus（文 1 つの箱）」「likely（推した行と手がかり）」「def（箱全体）」。
   行が箱の関数の外にある時（UI 8 の run_request）は、その行を持つ関数の名前と範囲も出す。
   いまは lines.js をページで動かしているが、推し方を myatlas に移せば、ソースの写し（`data/sources.js` 313 KB）は
   帯とその前後だけにできる。
2. **ソースの写し**：コードの行を見せるために、地図が指すファイル（26、313 KB）をページに入れる。重いので、
   別ファイルにして後から読むか（このページの形）、帯の前後だけを入れる。
3. **記録の exit と iret**：`traces.py` が enter・irq・switch・request しか残さない。exit・iret（と from・interrupted・syscall・
   trap・unwound）と `watched` を残せば、記録の段・待ち・道筋と、文脈ごとの回数が描ける（いまは trace-timeline が MyComputer の
   記録から作った `trace-full.js` を写して使っている）。`kernel.os-call` は OS_CALL の syscall の下の dispatch だけに付ける。
4. **路線図の配置**：`make atlas` で metro の `tools/precompute.mjs --warm` を回し、`layout.data.js` を地図の隣に置く
   （駅・地区・線の組の署名が変わった時だけ置き直す）。ページは配置を計算しない。
5. **節の関係の索引**：被参照（だれが・なぜ）は matrix の `model.js` をページで作っている。build.py で作って埋め込んでもよい。
6. **地図の文のずれ**：データの表が見つけた「13 語」と「15 語」の食い違い、result_out の条件の省略を atlas-check で拾い、
   ずれの説明をデータに持たせる（いまは data-journey の手書きの表）。
7. 流れの `start` は「地図のはじめ」の札として残し、開くのは手順 1 からにした。本体もそうするか決めて FORMAT.md に書く。
8. `tools/check.mjs` の検査（11px 未満の文字、重なり、回数の一致）を本体の検査に入れる。
