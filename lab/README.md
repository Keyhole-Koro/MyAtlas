# MyAtlas ラボ

MyComputer の文書マップ（MyAtlas）を、今のビューアより読みやすく見せる方法を、一晩で 14 通り試した試作の置き場。
最後に、その良い所を 1 つのビューアにまとめた（`next/`、「次のビューア」）。入口はギャラリー（`index.html`）。

## 目的

- 文書マップ（MyComputer の `docs/atlas`）は、70 の節を 5 つの層（アプリ・ライブラリ・OS サービス・カーネル・エミュレータ）と、
  層をまたぐ 3 つ（契約・実行の文脈・方針）に置き、2 つの流れを手順ごとにたどる。UI の要求は 11 手順＋もし 2、CPU 時間は 12 手順。
  4 つの節には中の紙（節の中の流れ）があり、記録が 1 回分ある（Editor で「x」を打った 1 回、279 件）。
- 今のビューア（`reference/`）は、サンドボックスの中で動く 1 枚の HTML として作った。層ごとの帯に、小さな札・番号の札・点線の枠・
  交差する矢印が詰まっていて、密。
- ここではその制約（CDN なし・保存なし・1 ファイル）を外して、系をいちばんよく見せる形を探した。どの試作も同じデータ（`data/`）を読み、
  地図とソースに無いことは描かない。決まりは `BRIEF.md`。
- ねらいは、本体のビューアに何を持ち帰るかを決めること。

## 動かし方

```sh
cd ~/Workspaces/MyAtlas-lab/lab
./serve.sh              # http://127.0.0.1:8765/ （./serve.sh 9000 でポートを変えられる）
```

ブラウザで http://127.0.0.1:8765/ を開くとギャラリー。カードの画面か「開く」で試作が開き、「NOTES.md」で作り手の記録が、
「画面 6 枚」でスクリーンショットが読める。ファイルとして直接開く（file://）と、多くの試作はデータを読めない。

### データを取り直す

```sh
python3 lab/export.py          # MyComputer は既定で ~/Workspaces/MyComputer（--root で変える）
```

書き直すのは `data/atlas.json`・`atlas.js`（地図）、`data/code.json`・`code.js`（節と手順のコードの場所）、
`data/src/`（地図が指すソースの写し）。次の 3 つは export.py では変わらないので、取り直した後に作り直す（どれも lab/ で）。

- trace-timeline の記録の全イベント（exit・iret を含む。MyComputer の `docs/atlas/traces/ui-request.json` から）：
  `node trace-timeline/tools/build-trace.mjs`
- metro の保存した配置（`layout.data.js`）：`node metro/tools/precompute.mjs --warm`
- terminal のブラウザ版で再生する画面（`web/frames-*.json.gz`）：`python3 terminal/tools/build_web.py`
- 次のビューアが持つデータの写し（`next/data/`）：`node next/tools/sync-data.mjs`（上の 2 つの後に）

### ほかの道具

- 画面を撮る：MyAtlas-lab で `node lab/tools/shot.mjs <id>/index.html out.png [--w 1440 --h 900 --dark --full --click … --eval …]`。
  ページがエラーを出すと終了コード 2。Playwright が無い時は `cd lab/tools && npm install && npx playwright install chromium`。
- 端末版：`python3 lab/terminal/atlas_tui.py`（`--render ui` で図だけ出して終わる）。
- コードと歩くの「エディタで開く」：serve.sh の代わりに `python3 lab/code-tour/server.py`（VS Code の `code` で開く）。
- 試作の検査：`node lab/metro/tools/check.mjs` と `node lab/matrix/check.mjs`（どちらも MyAtlas-lab で）、
  `node stack3d/tools/check-labels.mjs`（lab/ で）、`python3 test_atlas_tui.py`（lab/terminal/ で）。

## まとめ：次のビューア（`next/`）

14 の試作の良い所を、1 つの色・文字・部品の決まりでまとめたビューア。本体のビューアがどうなるとよいかを、触って確かめるためのもの。
http://127.0.0.1:8765/next/ で開く。くわしくは `next/NOTES.md`。

| 見方 | 何が見えるか | もとにした試作 |
|---|---|---|
| 歩く（開いた画面） | 道のり（層の上り下り）、手順の列と紙の入れ子、手順のカード（渡すデータ・文脈が変わる・記録の回数）、やりとり図、コードの行と吹き出し | code-tour・comic・seq-plus・graph-notebook・terminal・stack3d |
| 地図 | 路線図（共有する節は乗り換え駅、中の紙は支線、始発の札）。今の手順を線の上に出す | metro（保存した配置） |
| やりとり | 手順の文・矢印・記録の時刻の 3 列。紙はその場で開いて、外の手順を畳む | seq-plus |
| 記録 | スレッドごとの呼び出し、場面、キー → DOM の道筋、OS_CALL の数え直し | trace-timeline |
| データ | Request のフィールド × 手順（紙を開いた 22 手順）。線の色は値のあるメモリ | data-journey |
| 節のカード | 形・操作・不変・コードの場所・出てくる手順・被参照（だれが・なぜ） | matrix・graph-notebook |

- 5 つの見方は同じ手順と同じ節を選ぶ。場所はアドレス（`#v=walk&s=ui:3/os.gateway:1&n=os.gateway`）に残り、戻る・進むが効く。
- 地図とコードの食い違い（Request の 13 語と 15 語、result_out の条件）は、カード・吹き出し・やりとり・時刻表に「!」で示す。
- 2 つの独立したレビュー（初めての人と見た目、事実と作り）の点は、直す前で 3・4・3・4 と 4・4・3・4（読みやすさ・正しさ・仕上がり・まとまり）。
  重い指摘 5 つと中くらいの 13 は、すべて直した。
- フォルダだけで動く：相対パスの普通の `<script>` だけで、ネットワークもサービスワーカーも使わない。localStorage は try/catch の中だけ。
  file:// でも、オリジンの無いサンドボックス（artifact のサイト）でも動く。大きさは約 1.2 MB（スクリーンショットを除く）。
- 確かめ直す：`node lab/next/tools/check.mjs`（MyAtlas-lab で、約 3 分）。
- 本体に移す時に足すデータ：手順の行とその確かさ、ソースの写し、exit と iret を残した記録、保存した路線図の配置（`next/NOTES.md` に順序）。

## 順位と理由

順位は「今どれだけ読みやすく正しく見せるか」と「本体に持ち帰れるものの大きさ」を合わせて付けた。

1. **コードと歩く**（code-tour）：手順を選ぶと、それが起きる本物の行が開き、真下に吹き出しが出る。地図の文とコードを行き来する手間が消える。
   行の確かさを 4 段で見せ（起きる行 13、たぶんここ 28、欄 1、箱全体 7）、推した行も手がかり付きで出すので、49 手順のうち 42 で行まで読める。
   レビューの点は 4 つとも 4 で、いちばん高い。系全体の形は見せないので、全体図と組む前提。
2. **路線図**（metro）：1 枚で系全体が読める、ラボでいちばんの全体図。同じ節を乗り換え駅にしたので、流れと中の紙がどこで同じコードを通るかが見える。
   2 つの流れは tick() で出会い、submit の紙は要求の列で UI の要求に、Tasks.tick の紙は stats() で、charge_elapsed の紙は
   CPU 時間の置き場とタイマーの時計で CPU 時間に交わる。流れを 1 つずつ描く今のビューアには無い見え方。時刻表と電車で順も追える。
   押しても反応しなかった不具合は直っていて、今回マウスとタッチの試験で確かめた。弱みは、配置が保存した結果に頼ること。
3. **マンガで読む**（comic）：初めての人にいちばんやさしい。読み始めがはっきりしていて、交差する線が無く、ふきだしだけで UI の要求を
   1 分ほどで追える。層をまたぐ手順を床の段で見せる工夫と、表紙の「道のり」は本体にも使える。全体のつながりは見せないので、地図の代わりではなく入口。
4. **やりとり図をやり直す**（seq-plus）：今のやりとり図の置き換えにいちばん近い。手順の文・矢印・記録の時刻の 3 列がそろい、
   文脈の枠と層の色で誰が走るかが分かる。中の紙を開くと外の手順を畳むので、同じことが 2 回出ない。紙を全部開いた時の横の長さが残る。
5. **記録を時間で見る**（trace-timeline）：記録の本当の長さ・入れ子・待ちを見せる唯一の試作。キーから DOM の書き換えまでの 85% が
   列の待ちだったことなど、地図だけでは分からないことが見える。記録の OS_CALL の対応の誤りも見つけた。本体に入れるには、
   長さを描くデータ（exit・iret）は、MyAtlas の traces.py が 2026-11-20 から残すようになった。
6. **データの旅**（data-journey）：関数でなくデータの軸で見る、ほかに無い見せ方。gateway の役目（境界を越えて写し、owner を pid で上書きする）が
   色 2 つと斜線で言える。地図の古い数（13 語）も見つけた。印は手で書いた対応表から作るので、ほかの流れにすぐは広げられない。
7. **リンクでつながるノート**（graph-notebook）：読む用としてはいちばん。流れを歩くと手順ごとに節のノートが開き、文ごとの逆リンクと
   「文脈が変わる」の行が付く。ノートの中は今のビューアより読みやすいが、グラフの全体図は込み合う。
8. **ズームする地図**（zoom-atlas）：全体 → 手順 → 中の紙 → コードの行まで、場所を見失わずに寄れる唯一の試作。作りは大きいが、
   離れた時の全体図は名前が半分ほどしか出ず、まだ路線図ほど読めない。キャンバスなので読み上げにも弱い。
9. **自動配置の比較**（layout-lab）：見せ方ではなく物差し。今の地図の弱い所（削った札 12、段差 7、枠の誤り 11）を数で示し、直す規則を出した。
   提案は有望だが、同じ 6 枚で調整した規則なので、まだ勝ちとは言えない。物差し（`js/metrics.js`）は atlas-check に入れる価値がある。
10. **読み物で追う**（story）：章の始めの「道のりの表」と、2 箱へ寄るカメラは良い。中の紙をたたんで短くなったが、まだ約 41,000px あり、
    地図を探し回る用途には向かない。
11. **アイソメトリックの建物**（isometric）：マンガと並んで新しさは満点の絵。スレッドを人、OS_CALL をエレベーターにしたので、実行の文脈と
    ユーザ空間・OS の境目の説明に強い。止めた全体図としては今の地図より弱く、配置は手で決めた表。
12. **積み木の 3D**（stack3d）：データへの忠実さは満点で、層を下りて上る筋は見栄えがする。ただ 3D は奥が隠れ、地図として読むなら平面に劣る。
    収穫はラベルを 2 回に分けて置く方法と、それを数える検査。
13. **ターミナルで見る**（terminal）：技術的にはいちばん丁寧（幅に合わせた 6 段、本物の curses 画面との照合）。SSH 越しの相棒としては良いが、
    ブラウザのビューアの代わりではない。線の 3 段の塗り分けなどの規則は本体に使える。
14. **関係の行列と弦**（matrix）：行列そのものは密で、初めての人には読みにくい。持ち帰るのは、関係の索引（`model.js`）、被参照のパネル、
    記録について言えることだけを言う規則、層×層の表。

## 本体のビューアに取り入れること（優先順）

### まず：データを正す（どの見せ方にも効き、小さく直せる）

1. **手順の行を正す。** export.py（本来は MyAtlas）で、手順の行を「受ける側を呼ぶ（名前の後に括弧）・置き場に書く（代入）・return」の行に絞って確かめる。
   試作を作った時の code.json は 13 か所のうち 4 か所が別の行を指していた（ui 2、os.gateway 2 ともし A、kernel.cpu-time 6。同じ名前の引数や変数に当たっていた）。
   4 つの試作（code-tour・graph-notebook・story・zoom-atlas）が別々に同じ誤りを見つけた。**ラボの export.py はこの規則に直した**（2026-11-20）：
   3 か所は行を出さなくなり、kernel.cpu-time 6 は 111 行から 112 行（`g_clock_charged = now;`）になった。残る 10 か所は変わらない。そのうえで code-tour の推し方
   （`code-tour/lines.js` の 12 の決まり）か、`code-tour/NOTES.md` の表の 29 行を code.json に持たせれば、49 手順のうち 42 で行が出せる。
2. **記録を正す。** `traces.py` で exit・iret（と from・interrupted・syscall・trap）を残す。それだけで長さ・入れ子・待ちが描ける。
   `kernel.os-call` を付けるのは OS_CALL の syscall の下の dispatch だけにする。WAIT_NOTIFICATION の 3 回を外すと、
   OS_CALL は 12 回・887,983 命令ではなく 9 回・58,270 命令になる。`os_call` と `sys_wait_notification` には `syscall.masm` の置き場を入れる。
   **ここまでは MyAtlas の main で直した**（2026-11-20、8fd1de1）。`syscall.masm` の置き場はまだ。

### 次に：今のビューアを読みやすくする

3. **流れは手順 1 から開く。** データの `start`（手順 5）は「地図のはじめ」の札にして「1 から見る」を添える。自動再生は、まだ動かしていなければ 1 から。
   中の紙へは「中の紙を見る」で誘う。手順 5 から開くことは 5 つの試作（code-tour・zoom-atlas・stack3d・graph-notebook・data-journey）のレビューで指摘され、どれも 1 から歩ける形に直した。
4. **手順からコードの行へ。** 手順を選んだら、そのコードを起きる行で開き、吹き出しを行の真下に置く。確かさは見た目で分ける：
   記録された行は濃い帯、推した行は点線と「たぶんここ」と手がかり、どちらも無ければ箱全体。行が入る関数を帯にして「〜の中」と書く。（code-tour）
5. **線と札は 3 段。** 今の手順だけ太く動詞付き、通った手順は落ち着いた 1 色、これからは灰。番号の札は必ず出し、動詞や説明は
   場所があれば足す（2 回に分けて置く）。文脈が変わる手順では「文脈が変わる A → B」をカードに出す。（terminal・stack3d・graph-notebook）
6. **置き方の規則と物差し。** 今の地図に、札の場所を先に取る（帯の中で続く手順は 1 行にし、札は矢印の上）、24px 以内の段差を消す、
   文脈の枠は段ごとの長方形、を当てる。`layout-lab/js/metrics.js`（交差・札の重なり・線から離れた札・段差）を `make atlas-check` に入れ、
   見た目の退行を数で止める。（layout-lab）

### そのあと：新しいタブ

7. **全体図に路線図。** 同じ節を乗り換え駅に、中の紙を支線に、始発の札と線の中の「›」で向き、時刻表と地図の区間の連動。
   配置は `make atlas` で precompute して保存する。（metro）
8. **やりとり図を作り直す。** 手順の文・矢印・記録の時刻の 3 列。中の紙をその場で開き、紙が描く外の手順は「＝紙の 8」と畳む。
   文脈の枠と層の色、呼び出しの入れ子での活性化の棒。（seq-plus）
9. **記録のタブ。** スレッドごとのフレームグラフ、要所だけにたたむ表示（たたんだ中を選ぶと開き、外すと戻る）、場面の番号の札、
   記録外を詰めた時間の軸、列を通る矢印、キー → DOM の道筋。2 の直しが前提。（trace-timeline）
10. **渡すデータのタブ。** schema を持つ流れなら、フィールド × 手順の表。線の色は値のあるメモリ、斜線は「まだアプリ次第」、
    出どころは「印 → 地図の文 → コードの行」。印を手で書かずに済むよう、まず ops と data.fields から作れる所まで自動にする。（data-journey）
11. **節のカードと入口の図。** 節のカードに被参照（だれが・なぜ指しているか。文ごとに出し、1 節 1 回で数える）を出し、関係の索引は
    matrix の `model.js` を土台にする。流れの見出しには「道のり」（層の上り下りを 1 列 1 手順で描く、高さ 100px ほどの図）を置く。
    （matrix・graph-notebook・comic・story）

## 残っている問題

### データ（ラボの外）

下の 2 つは 2026-11-20 に main で直した。ラボのデータと試作は直す前の地図と記録のままで、「!」の印もその時の食い違いを指す。

- traces.py の OS_CALL の対応・exit と iret の欠け（上の 2）。MyAtlas の 8fd1de1 で直した。試作はそれぞれページの側で補っている。手順の行の誤り（上の 1）は、ラボの export.py では直した。
  trace-timeline は MyComputer の記録ファイルの写し（`trace-timeline/data/trace-full.js`）に頼っている。
