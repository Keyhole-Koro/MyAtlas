# ターミナルで見る（terminal）

文書マップ（MyAtlas）を、端末の中で読む TUI。Python 3 の標準ライブラリ（curses）だけで動き、
SSH 越しでも、46 桁の狭い端末（スマホの SSH アプリ）でも使える。

```
python3 lab/terminal/atlas_tui.py            # 対話（? でキー一覧）
python3 lab/terminal/atlas_tui.py --render ui            # 図だけ出して終わる
python3 lab/terminal/atlas_tui.py --render cpu --step 5 --width 120
python3 lab/terminal/atlas_tui.py --render os.gateway --view route --width 60
python3 lab/terminal/atlas_tui.py --list     # 流れ・紙・節の id
```

ブラウザでは `lab/terminal/index.html`（serve.sh で `http://127.0.0.1:8765/terminal/`）。
これは同じ Python の描画を書き出して再生しているので、端末で見えるものと一字一句同じ。

## アイデア

- **層は横の帯、手順は番号付きの線。** 層ごとのレーンに箱を置き、手順を直交の線（A* で引く）で結び、
  線の上には番号札だけを載せる。言葉は下の「手順」の面に出す。
- **「今」だけが光る。** 今の手順の線は太線（━ ┃ ┅）と青い札、箱も太い枠（┏━┓）。通った手順は落ち着いた青、
  これからの手順は灰。色は状態、線の形は種類（─ 呼び出し・読み書き、═ syscall、┄ 列を通す、
  ◆┈ 通知、╌▷ 戻り）。今の手順の札にだけ動詞を足す（「5 時計を読む」）。
- **下に 3 つの面。** 手順（動詞・誰から誰へ・層をまたぐか・渡すもの・もし・中の紙・コードの行）、
  渡すもの（構造体の欄を全部並べ、この手順で渡る欄に印「10 欄のうち 4」）、説明（節の型・引数・本文・出る所）。
- **幅と高さで詳しさを落とす。** 6 段：全部 → 間を詰める → 短い名前（short）→ 層の名前を縦書き（縦中横つき）→
  箱は名前だけ → 上下の空き行も詰める。どれも幅に入らない時は「道のり」（縦の一本道。層ごとに字下げ）に
  自動で切り替える。
- **端末らしい道具。** `c` でその手順のソース（地図のデータにある行、無ければ行先の定義）を色付きで、
  `t` で記録（Editor で「x」を打った 1 回）をスレッドごとの時間軸とできごとの一覧で、`n` で層 → 節の一覧、`/` で探す。
  記録の行には、その行が流れのどの手順の場面かを札で付け（「UI の要求 3」など）、Enter でその手順へ飛ぶ。
- 手順を進めると、点が今の線を出元から行先へ走る（端末でもブラウザでも。`--still` で止める）。

## 使い方（キー）

| キー | すること |
|---|---|
| ← → | 前の手順・次の手順（Home は最初の手順、End は最後の手順。「もし」は a で） |
| Enter / Esc | 中の紙に入る（箱に「中の紙」の札がある時）・出る |
| a | 「もし」の手順（ui の 5 の代わりの A・B）へ、戻る |
| ↑ ↓ | 箱を選ぶ（説明の面がその節になる。画面の外の箱なら地図を送る） |
| PgUp PgDn / i | 説明を送る / 説明を全面に |
| v | 地図 ⇄ 道のり |
| c | この手順のコード |
| 1 2 / n / t / ? / q | 流れ・節の一覧・記録・キー一覧・終わる |
| マウス | 箱で選ぶ、番号札でその手順へ、タブ・下のキーも押せる |

`--ascii`（罫線を ASCII で）、`--theme light`（明るい端末）、`NO_COLOR` も効く。
地図は手順 5 から開く（地図のデータの start）。右上に「Home で手順 1 から」と出る。

ブラウザ版は、キー・画面のクリック（タブ・番号札・箱・下のキーの帯）・下のボタンで動く。大きさ 3 種
（160×44・112×34・46×40）と暗い・明るいを切り替えられる。

## できていること

- 流れ 2 本（UI の要求 11 手順＋もし 2、CPU 時間 12 手順）、中の紙 4 枚（入れ子も：gateway → submit）、
  70 節、記録 279 件、コード 26 ファイル。すべて lab/data から。地図にない事実は書いていない
  （図の SVG は端末で描けないので、題と aria-label の説明文を出す）。
- 全角 2 桁の幅、禁則（行頭に 、。）が来ない。長い名前は . _ / の後で折る）、バランスの良い折り返しを自前で。
- 記録の札は「その手順の場面の時だけ」付ける。割り込みの原因と service、同じスレッドで直前に入った節、
  列にまだ残っている要求を見て決める。違う時は札を付けず、右の面に「どの手順でもない」と理由を書く
  （例：手順 3 は service が REQUEST の OS_CALL。この OS_CALL の service は POLL）。
- 確かめたこと：
  - pyte（端末エミュレータ）で本物の curses 画面を読み、描いたグリッドと全行一致
    （`tools/capture.py`。46〜160 桁、流れ・選択・説明・記録・節の一覧）。矢印キーは ESC O / ESC [ のどちらでも効く。
  - テスト 16 本（`python3 test_atlas_tui.py`）：全図の全手順 × 9 つの大きさ × 地図と道のり、乱打 3,600 キー、
    線が箱を通らない、番号札が重ならない・箱に乗らない・矢じりを消さない・他の線の端や曲がり角に乗らない、
    呼び出しと戻りの組が同じ列に積まれない、160×44 と 112×34 で流れの地図が切れずに入る、節の一覧の名前が切れない、
    箱の名前が切れない、禁則。
  - 書き出した全画面を調べ、PgDn が出ている画面では PgDn で送れること、ブラウザで使えないキー（/ と q）の
    案内が無いことを確かめた。
- ブラウザ版：状態を書き出して再生（160×44 で約 7,300 画面・gzip 1.0 MB、112×34 で約 8,300 画面・0.7 MB、
  46×40 で約 9,000 画面・0.7 MB）。画面ごとのクリックできる所も書き出してある。`--render ui` の出力も同じ描き方で載せた。

## できていないこと・弱いところ

- 箱の配置は焼きなまし（固定シード）＋ A* の自動。参照版の手で整えた配置ほど締まらない所がある
  （ui の手順 3 と B は回り道）。CPU 時間は呼び出しと戻りの組を階段に置いたので、上の 3 層の左側はまだ空く。
- 罫線・▶・◆ は East Asian Ambiguous。日本語向けに「曖昧幅を全角」にした端末では崩れる → `--ascii`。
- 256 色の近似色で描き、背景も塗る（端末の配色は使わない）。
- 記録を流れに沿って自動で再生する（参照版の「記録で流す」）はまだ。
- ブラウザ版は書き出した操作だけ：検索（/）は端末版のみ。
- 112×34 で CPU 時間の地図を全部入れるため、手順の面が 5 行になり、最後の「コード」の行が隠れる（c で見られる）。
- 140 桁前後の端末では、高さが足りず「名前だけの箱」の段になることがある（詳しい段は高さを食う）。
- 検証用の `.venv`（pyte、約 20 MB、git では無視）は本体にもページにも要らない。消してよい。

## メインの viewer に持ち帰れそうなこと

1. 線の 3 段階：今だけ太く強く、通った手順は落ち着いた 1 色、これからは灰。全部の線に色を付けない。
2. 色は状態、形は種類。線種（実線・二重・破線・点線と ◆・中が空の矢じり）で手順の種類を分ける。
3. 線の上は番号札だけ。言葉は手順の面へ。今の手順の札にだけ動詞を足す（「5 時計を読む」）。
4. 幅で詳しさを段階的に落とし、最後は縦の一本道（層ごとに字下げ）。スマホでも読める。
5. 渡すもの：構造体の欄を全部並べ、渡る欄に印。何が渡り、何が渡らないかが一度に見える。
6. 実行の文脈は点線の枠でなく薄い面。線や札と取り合わない。
7. 記録の「だれが走っているか」の帯（スレッドごとの時間軸）と、行ごとの手順の札。札は場面が合う時だけ付け、
   合わない時は理由を言う（同じ関数でも、呼ばれた場面が違えば別の話）。
8. 呼び出しと戻りの組は同じ列に積まず、階段にして 1 組ずつの輪にする（線 4 本が 1 本の隙間に詰まらない）。
9. 描画を 1 つにして、端末・テスト・ブラウザで同じ画面を使う作り（状態を書き出して再生）。

## レビューの後に直したこと

レビュー（読みやすさ 3・忠実さ 4・仕上げ 3・新しさ 4）で挙がったものを全部直した。

- **記録の札が違う手順を指していた（高）。** 節が同じなら札を付けていたのをやめ、場面で決める。
  irq_dispatch・tick は timer の割り込みの後だけ CPU 時間 1・2、reschedule は tick から呼ばれた時だけ 3、
  syscall.dispatch は service が REQUEST の時だけ UI の要求 3。gateway の中・submit の中・serve も同じ考えで。
  違う時は「どの手順でもない」と理由を出す。
- **112 桁以下で番号札が矢じりを消していた。** 札は線の途中だけに置き、矢じり・線の端・曲がり角には乗せない。
  全図・全手順・全 6 段で、描いた後の矢じりが残っていることをテストする。
- **ブラウザ版で、押せそうで押せない所・読めない説明があった。** 画面ごとのクリックできる所（タブ・番号札・
  箱・下のキーの帯）を書き出した。↑↓・i・PgUp PgDn も全部の大きさで書き出した。/ と q の案内は出さない。
  説明の面は、送れる時は「13/16 PgDn」、最後まで来たら「16/16 PgUp」と出す。
- **46 桁の記録が崩れていた。** 目盛りはぶつからない数だけ、見出しは折り返す、スレッドは色の印 1 字、
  手順の札は 2 行目に。
- **CPU 時間の地図が偏り、112×34 では上が切れていた。** 列を決める費用に「呼び出しと戻りの組（7 と 12、8 と 11）を
  同じ列に積まない」を足した。tick() → stats() → fill(out) が階段になり、fill(out) は charge_elapsed の真上
  （9 がまっすぐ下りる）。開く手順（5）は少し重くして短い線のまま。高さが足りない時の 6 段目（上の層の箱の上と
  下の層の箱の下の空き行を詰める）を足し、112×34 で 5 層とも入る。ui と中の紙 4 枚の配置は変わらない。
- **↑↓ で選んだ箱が画面の外だった。** 選んだ箱が見えるように地図を送る。説明の面が無い幅では、手順の面の代わりに
  選んだ箱の説明を出す。
- **名前が途中で切れていた。** 節の一覧は名前が全部入る幅にし（種類の欄を詰め、「実行の文脈」は「文脈」に）、
  層の説明は折り返す。切れる所には … を付ける。`--render` の手順一覧は折り返す。スマホの手順の帯は「もし A B」まで入る。
- **始まりが分かりにくく、End が最後の手順に行かなかった。** 「地図はここ（手順 5）から。Home で手順 1 から」を出し、
  ページに Home のボタンを置いた。End は最後の本線の手順（11）へ。
- **これからの線と字が暗すぎた。** これからの箱の副題は薄い灰をやめ、灰の線と字・箱の枠・明るい端末のコメントの色を
  上げた（地と実行の文脈の面の上で、字は 4.5:1、線は 3:1 以上。暗い・明るいの両方）。
- **通知と列を通すが見分けにくかった。** 通知は出る所に ◆ を付け、点を 1 マスに 1 つにした（列を通すは短い破線 2 つ）。
  凡例は大きく描き、「読み書き」も足した。
- 細かいこと：エミュレータの帯は「この流れの箱はない」と薄く、MyEmulator も出す。`--list` は「11 手順 ＋ もし 2」。
  広い画面の記録ではスレッド名をデータのまま（kernel: を薄く）。スマホでは `--render` の見本を横に送れる大きさで、
  コマンドは折り返さない。
- レビューの外で見つけたもの：ブラウザ版の矢じりの先が、道のりの箱の題や手順の帯の数字に刺さっていた
  （canvas の矢じりは隣のマスへはみ出して箱の枠に届く作り）。隣のマスが線か空白の時だけはみ出すようにした。
  `--screen --keys` と検証の道具は、本物と同じく 1 キーごとに描いてから押す（PgDn が効くように）。

## ファイル

- `atlas_tui.py`：本体（データ、配置と線引き、画面、curses、CLI）。標準ライブラリだけ。
- `test_atlas_tui.py`：テスト。
- `tools/build_web.py`：ブラウザ版の画面を書き出す。`tools/capture.py`：pyte で本物の画面と照合
  （`.venv` に pyte を入れて使う。本体には要らない）。`tools/devframe.py`：1 画面を dev/ に書く。
- `web/term.js`：フレームを canvas に描く（罫線・矢じり・ブロック・◆ は図形で描くので、フォントに依らず揃う）。
- `web/page.js`, `web/page.css`, `index.html`：ページ。`web/frames-*.json.gz`：書き出した画面。
